# Pilot 开发路线图

Pilot 是基于 pi SDK 的本地 AI 编程桌面客户端。面向开发者的核心流程是打开项目、交代任务、审查和验证代码改动，再将选中的改动提交到 Git。桌面界面负责让当前项目、Agent 正在做的事、待审批的操作和验证结果始终可见。页面结构和交互规则见设计规范。[设计规范](./DESIGN.md)

## 开发顺序

P0 为首个日用版的交付条件，P1 为日常效率和发行完善，P2 为扩展能力。表中每项可拆成独立提交，详细验收写在对应里程碑内。

| 顺序 | 里程碑 | 优先级 | 可独立交付的模块 |
| --- | --- | --- | --- |
| 1 | [项目与会话恢复](#1-项目与会话恢复) | P0，已完成 | 项目入口与会话目录绑定、最近项目与会话分组、会话设置、运行归属、在途持久化、项目指令 |
| 2 | [Git 审查与验证](#2-git-审查与验证) | P0，已完成 | Git 变更、差异与撤销、测试结果、暂存与提交 |
| 3 | [基础稳健性](#3-基础稳健性) | P0 | 单实例、设置损坏保护、界面崩溃恢复、退出确认、窗口与布局记忆、运行期间不休眠 |
| 4 | [安全与可靠性](#4-安全与可靠性) | P0 | 命令授权范围、危险命令、运行对象拆分、命令执行、失败重试、模型能力配置、上下文压缩、技能按需加载、会话追加写、代理验证 |

里程碑 3 最先做。重复启动、设置损坏和界面崩溃会直接丢数据或让窗口不可用，这几项彼此独立，改动范围小。里程碑 4 先于里程碑 5。授权范围和命令执行的问题会在真实项目里造成损失，重试和压缩决定长任务能否跑完，这些不依赖界面调整。里程碑 5 内部先做外壳与统一审查面板，后续模块都落在新结构上。真实模型验收和打包可以与核心开发并行。并行任务依赖会话与运行的隔离，运行对象拆分在里程碑 4 先完成。

### 1. 项目与会话恢复

已绑定的会话使用自己的目录。切换会话时，原任务继续使用发起时的目录、模型和权限，运行结束后保存到原会话。[AgentHost 实现](../src/main/agent-host/host.ts)

- [x] **项目入口与会话目录绑定。** 打开本地文件夹后，新聊天沿用项目目录，并在创建会话记录时保存目录关联。会话标题下显示目录，文件搜索、引用预览和工具使用该目录。旧会话保留历史，可手动关联项目。
- [x] **最近项目与会话分组。** 侧栏可在重启后重新打开最近项目，包括还没有会话的目录。会话按项目分组，置顶会话在组内优先显示。旧会话可从「未关联项目」找到并关联到最近项目或另一文件夹。Git 项目在会话标题旁显示当前分支。
- [x] **会话设置。** 按会话保存模型选择、未发送的草稿和权限模式。缺少会话设置时使用全局默认值，也可在输入区选择「跟随全局默认」。首次输入草稿或设置会话覆盖后，即可从侧栏重新打开尚未发送消息的会话。
- [x] **运行归属。** 主进程用会话与运行标识关联流式回复、工具结果、审批和停止操作。切回原会话可以查看进度、处理审批或停止。应用同时保留一项活动任务，其他会话可以编辑草稿，尝试发送时会提示任务所在的会话。
- [x] **在途保存与恢复。** 在收到用户消息、完成工具步骤和回合结束时保存转录和运行状态。异常退出后显示「已中断」，可在原工作目录从已保存的上下文继续。续跑保留已记录的工具结果，并拦住已开始执行的相同文件写入、编辑和命令。未保存结果的操作显示为结果未知。
- [x] **项目指令。** 按会话绑定的目录加载项目根目录的 `AGENTS.md`。会话标题旁的「指令」显示加载的文件路径和生效顺序。发生冲突时，应用指令优先，其后依次是项目指令、会话指令（未设置时用全局个性化）、技能。运行期间使用启动时加载的内容，下一次任务重新读取文件。

验收时交替打开两个项目。在流式回复、等待审批和工具运行时切换会话，检查消息、工作目录和请求的归属。停止任务和重启后复查草稿、部分结果与历史数据。

### 2. Git 审查与验证

- [x] **Git 变更。** Agent 执行前记录暂存区、工作树和未跟踪文件的基线。从会话标题旁的「Git 变更」查看内置工具和命令产生的新增、修改、删除与重命名。面板标出已有改动、任务期间的变化和归属不明的混合变更。重新打开会话可查看最近一次任务结束时的清单。[Git 变更面板](../src/renderer/src/components/ai/git-changes-panel.tsx)
- [x] **差异与撤销。** 在 Git 变更面板展开文件查看逐行差异，点击新版本行号可在 VS Code 定位到工作树中的对应行。打开「任务检查点」，可按文件或区块预览撤销范围。确认时复核当前文件和暂存内容，遇到归属不明、暂存变化或后续编辑时提示冲突并保留文件。已完成的检查点可随会话重开。普通文件夹继续使用已有工具差异与撤销。[Git 差异和撤销预览](../src/renderer/src/components/ai/git-diff-preview.tsx)
- [x] **验证入口。** 从会话标题旁打开「验证」，运行项目的测试、类型检查、构建或手动输入的验证命令。显示工作目录、命令、实时输出、退出码和耗时。每次执行保存到原会话并关联所属任务与运行。切换会话时命令继续运行，重启后可从原会话查看结果。停止会结束命令和子进程，重跑沿用原命令与目录并新增一条记录。[验证界面](../src/renderer/src/components/ai/verification-dialog.tsx)
- [x] **暂存与提交。** 在 Git 变更面板按文件或文本区块暂存，再从实时暂存区选择要提交的文件或区块。填写提交信息前可预览所选内容的完整 Git 差异。提交时复核分支和暂存区，成功后显示提交号及分支并刷新清单。其余暂存内容与工作树改动保留，仍可查看任务变更记录和检查点。[Git 提交预览](../src/renderer/src/components/ai/git-commit-dialog.tsx)

验收时使用同时含暂存、未暂存和未跟踪文件的仓库，通过内置工具与命令分别修改代码。复查 diff，撤销一块任务改动，运行测试并提交选中的内容。原有改动和暂存状态应按本次选择保留。

### 3. 基础稳健性

这一组补上桌面应用的基础保护，出问题时不丢数据，窗口可以恢复。各项互相独立，可以逐个提交。[主进程入口](../src/main/index.ts) · [设置存储](../src/main/settings/index.ts)

- [x] **单实例。** 对同一数据目录再次启动时会聚焦已有窗口，窗口最小化时先还原。后启动的进程在加载设置和会话前退出。Windows 目录联接指向同一实际目录时也会唤醒原窗口。通过 `--user-data-dir` 指定独立目录的验收实例可与日常实例并存。[Windows 回归验证](../scripts/verify-windows.mjs)
- [x] **设置损坏保护。** 设置内容无法解析或结构损坏时，先把原文件另存为带时间戳的备份，再保存默认设置。界面显示备份路径。恢复受阻时保留原文件并暂停保存，恢复文件访问后可重试。会话索引损坏时备份原索引，保留仍有效的条目，再根据转录和草稿文件补回缺失的会话。[设置存储](../src/main/settings/index.ts) · [会话存储](../src/main/agent-host/session-store.ts)
- [x] **界面崩溃恢复。** 组件报错时显示原因及「重新加载」和「查看日志」。渲染进程退出或无响应时，主进程通过原生提示重新加载已有窗口。重载后接回当前会话、主进程中继续运行的任务、草稿和待审批请求。[界面错误边界](../src/renderer/src/components/app-error-boundary.tsx) · [窗口恢复](../src/main/window-recovery.ts)
- [x] **退出确认。** 有任务或验证命令在运行时，关闭窗口、退出和更新重启都先询问。取消后继续运行。确认后停止任务、保存可继续的检查点，结束验证命令并记录已中断，再关闭、退出或安装。Agent 命令的整棵进程树清理见里程碑 4。[退出流程](../src/main/desktop-exit.ts)
- [x] **窗口与布局记忆。** 按数据目录恢复窗口位置、大小和最大化状态，标题栏移出可用工作区时将窗口移到主屏中央。记住侧栏宽度和收起状态。审查面板的宽度随里程碑 5 的统一审查面板处理。[窗口状态](../src/main/window-state.ts) · [侧栏偏好](../src/renderer/src/lib/preferences.ts)
- [x] **运行期间不休眠。** Agent 任务或验证命令运行时阻止系统自动睡眠，屏幕仍可按系统设置熄灭。等待审批和停止收尾也属于运行期间。最后一项工作完成、失败或停止后解除。[睡眠阻止](../src/main/sleep-blocker.ts)

验收时连续启动两次，确认只有一个窗口并被带到前台。手工写坏设置文件后启动，确认界面显示的备份保留原文件内容。模拟备份失败，确认保存被拦截。写坏会话索引后重启，从侧栏打开已有聊天和草稿。在任务运行时结束渲染进程，确认窗口恢复后任务仍在进行。运行中按 `Ctrl+Q`，确认出现询问，取消后任务继续，确认后没有残留进程。移动并调整窗口和侧栏后重启，确认恢复到原来的位置和宽度。同时运行 Agent 任务和验证命令，确认最后一项工作结束后解除睡眠阻止。

### 4. 安全与可靠性

这一组先解决会造成实际损失或让任务半途而废的问题。[权限门实现](../src/main/agent-host/permissions.ts) · [命令工具](../src/main/agent-host/tools/bash.ts)

- [ ] **命令授权范围。** 现在对任意一条命令选择「总是允许」，保存的规则只有工具名，之后所有命令都不再询问。改为按命令前缀保存规则，例如 `pnpm test`、`git status`。含管道、重定向、命令连接符或子命令替换的命令逐段匹配，任意一段未授权就询问。审批卡和设置页显示规则覆盖的范围。旧的无范围命令规则在升级时停用，并在设置页提示重新授权。
- [ ] **危险命令。** 危险规则先于授权规则和完全访问模式判定，命中后始终询问，只能允许一次。规则补充 `git push --force`、`git reset --hard`、`git clean`、`git checkout -- .`、下载后直接执行的管道、磁盘与分区工具，以及指向项目目录之外的递归删除。完全访问模式的说明写明这一例外。
- [ ] **运行对象拆分。** Agent 主机现在在一个文件里管理运行生命周期、会话、Git 审查和文件变更，全应用只有一个运行实例。把一次运行的状态、审批、检查点和中止逻辑拆成独立对象，对外行为不变。命令执行和失败重试落在新结构上，里程碑 7 的多会话并行以它为前提。[AgentHost 实现](../src/main/agent-host/host.ts)
- [ ] **命令执行。** 停止和超时时结束整棵进程树，Windows 使用 `taskkill /T /F`，其他平台结束进程组。失败时返回给模型的输出与成功时使用同一上限，超长时保留开头和结尾并标明省略的长度。超时上限可由模型在限定范围内指定，超时后的结果写明已运行时长。长期运行的命令（开发服务器、监听模式）转入里程碑 6 的终端。
- [ ] **失败重试。** 模型请求遇到网络错误、限流和服务端错误时自动退避重试，界面显示第几次重试和等待时间，可立即取消。重试用尽后，错误卡显示原因和 `重试` 按钮，重试沿用原任务和已保存的上下文。凭据、额度和模型能力错误不自动重试，给出对应的设置入口。[模型适配](../src/main/agent-host/models.ts)
- [ ] **模型能力配置。** OpenAI 兼容端点的模型现在固定按 128k 上下文、8192 输出上限、仅文本、不支持思考、费用为零处理。改为优先使用端点或模型目录返回的能力，读不到时用默认值，并可在设置里按模型填写上下文长度、输出上限、图像输入和思考支持。上下文用量、压缩时机和附件能力提示都使用这些值，因此排在上下文压缩之前。
- [ ] **上下文压缩。** 占用接近模型上下文上限时自动压缩较早的对话，保留原始转录、当前计划、关键文件引用和待解决事项。用量弹层提供手动压缩，`/compact` 可附带保留重点。对话中标出压缩发生的位置，可展开查看摘要。较早的长工具输出优先裁剪，界面仍可查看原文。上下文超限错误提供 `压缩并重试`。
- [ ] **技能按需加载。** 现在启用的技能会把正文全部拼进每次请求的系统提示词，注入的内容也没有说明技能目录在哪里，技能自带的脚本和参考文件用不上。改为只注入技能的名称、说明和所在目录，模型用到时再读取正文和附带文件，读取范围限定在该技能的目录内。设置页可以查看技能的内容和来源，也可以删除。项目里的 `.agents/skills` 和 `.claude/skills` 直接生效，不需要先导入。[技能实现](../src/main/agent-host/skills.ts)
- [ ] **会话追加写。** 现在每次保存都同步重写整份转录，一轮任务里会保存多次。先用长会话加大段工具输出的夹具测量保存耗时，确认有收益后改为按消息追加，回合结束或压缩时再整理成完整文件。保留原子替换和损坏行跳过。[会话存储](../src/main/agent-host/session-store.ts)
- [ ] **代理验证。** 先验证，再决定是否需要开发。在必须经代理访问模型的网络下，实测模型请求、模型目录、连通性测试、HTTP 类型的 MCP 服务和应用更新是否跟随系统代理与 `HTTPS_PROXY`。有不通的环节再增加代理设置，全部可用时只在文档里写明行为。

验收时在真实 Git 项目中授权 `pnpm test` 后运行 `pnpm test && git push --force`，应再次询问并标红。启动一个会派生子进程的命令后停止，确认没有残留进程。断网后发送消息，检查自动重试、取消和手动重试。把一个兼容端点模型的上下文长度改小，确认用量百分比和压缩时机随之变化。启用十个技能后发送消息，确认请求里只有技能清单，模型用到某个技能时才读取正文，并能运行技能目录里的脚本。用长会话触发自动压缩后继续任务，确认计划和关键文件仍在上下文中，重启后原始转录完整。

3. 中途断开网络再恢复，确认任务自动重试或可以手动重试并继续。
4. 在审查面板查看本轮和原有的变更，按区块撤销一处任务改动，在验证页签重跑测试并查看退出码与日志。
5. 暂存并提交选中的改动。重启应用后打开同一项目，确认会话、验证结果和 Git 状态仍对应原任务。
6. 任务运行时再次启动 Pilot，应回到已打开的窗口。此时关闭窗口，应先询问是否停止任务。

## 工程与交付约定

Agent、pi SDK、工具执行和密钥使用留在 Electron 主进程。渲染层通过预加载层的类型化 IPC 消费 `UiAgentEvent`，权限由 `beforeToolCall` 判定。已启用技能与项目指令由主进程组装，模型调用产生的用量事件仍发送累计快照。

会话和历史转录沿用按会话保存的 JSONL。持久化格式变更兼容旧数据，工作区路径校验、审批和撤销以运行绑定的目录为准。依赖版本以 `pnpm-lock.yaml` 和 CI 为准，pi 升级集中在 Agent 主机与适配层。[IPC 契约](../src/shared/contract.ts)

每完成一个独立模块，提交并推送当前分支，在开发完成记录中追加日期、交付内容、提交和验收结果。完成路线图中的事项后更新对应状态。代码走工程规范的八步验证，界面模块额外跑对应的桌面场景并核对设计规范的提交前自检。界面结构或交互规则有变化时，同一个提交里更新设计规范。发布产物记录所用提交和目标平台。[工程操作规范](../AGENTS.md) · [设计规范](./DESIGN.md)
