# Pilot 开发路线图

Pilot 是基于 pi SDK 的本地 AI 编程桌面客户端。面向开发者的核心流程是打开项目、交代任务、审查和验证代码改动，再将选中的改动提交到 Git。桌面界面负责让当前项目、Agent 正在做的事、待审批的操作和验证结果始终可见。页面结构和交互规则见设计规范。[设计规范](./DESIGN.md)

## 开发顺序

P0 为首个日用版的交付条件，P1 为日常效率和发行完善，P2 为扩展能力。表中每项可拆成独立提交，详细验收写在对应里程碑内。

| 顺序 | 里程碑 | 优先级 | 可独立交付的模块 |
| --- | --- | --- | --- |
| 1 | [项目与会话恢复](#1-项目与会话恢复) | P0，已完成 | 项目入口与会话目录绑定、最近项目与会话分组、会话设置、运行归属、在途持久化、项目指令 |
| 2 | [Git 审查与验证](#2-git-审查与验证) | P0，已完成 | Git 变更、差异与撤销、测试结果、暂存与提交 |

里程碑 3 先于里程碑 4。授权范围和命令执行的问题会在真实项目里造成损失，重试和压缩决定长任务能否跑完，这些不依赖界面调整。里程碑 4 内部先做外壳与统一审查面板，后续模块都落在新结构上。真实模型验收和打包可以与核心开发并行。并行任务依赖会话与运行的隔离。

### 1. 项目与会话恢复

已绑定的会话使用自己的目录。切换会话时，原任务继续使用发起时的目录、模型和权限，运行结束后保存到原会话。[AgentHost 实现](../src/main/agent-host/host.ts)

- [x] **项目入口与会话目录绑定。** 打开本地文件夹后，新聊天沿用项目目录，并在创建会话记录时保存目录关联。会话标题下显示目录，文件搜索、引用预览和工具使用该目录。旧会话保留历史，可手动关联项目。
- [x] **最近项目与会话分组。** 侧栏可在重启后重新打开最近项目，包括还没有会话的目录。会话按项目分组，置顶会话在组内优先显示。旧会话可从「未关联项目」找到并关联到最近项目或另一文件夹。Git 项目在会话标题旁显示当前分支。
- [x] **会话设置。** 按会话保存模型选择、未发送的草稿和权限模式。缺少会话设置时使用全局默认值，也可在输入区选择「跟随全局默认」。首次输入草稿或设置会话覆盖后，即可从侧栏重新打开尚未发送消息的会话。
- [x] **运行归属。** 主进程用会话与运行标识关联流式回复、工具结果、审批和停止操作。切回原会话可以查看进度、处理审批或停止。应用同时保留一项活动任务，其他会话可以编辑草稿，尝试发送时会提示任务所在的会话。
- [x] **在途保存与恢复。** 在收到用户消息、完成工具步骤和回合结束时保存转录和运行状态。异常退出后显示「已中断」，可在原工作目录从已保存的上下文继续。续跑保留已记录的工具结果，并拦住已开始执行的相同文件写入、编辑和命令。未保存结果的操作显示为结果未知。
- [x] **项目指令。** 按会话绑定的目录加载项目根目录的 `AGENTS.md`。会话标题旁的「指令」显示加载的文件路径和生效顺序。发生冲突时，应用指令优先，其后依次是项目指令、会话指令（未设置时用全局个性化）、技能。运行期间使用启动时加载的内容，下一次任务重新读取文件。

验收时交替打开两个项目。在流式回复、等待审批和工具运行时切换会话，检查消息、工作目录和请求的归属。停止任务和重启后复查草稿、部分结果与历史数据。

### 2. Git 审查与验证

- [x] **Git 变更。** Agent 执行前记录暂存区、工作树和未跟踪文件的基线。从会话标题旁的「Git 变更」查看内置工具和命令产生的新增、修改、删除与重命名。面板标出已有改动、任务期间的变化和归属不明的混合变更。重新打开会话可查看最近一次任务结束时的清单。[Git 变更面板](../src/renderer/src/components/ai/git-changes-panel.tsx)
- [x] **差异与撤销。** 在 Git 变更面板展开文件查看逐行差异，点击新版本行号可在 VS Code 定位到工作树中的对应行。打开「任务检查点」，可按文件或区块预览撤销范围。确认时复核当前文件和暂存内容，遇到归属不明、暂存变化或后续编辑时提示冲突并保留文件。已完成的检查点可随会话重开。普通文件夹继续使用已有工具差异与撤销。[Git 差异和撤销预览](../src/renderer/src/components/ai/git-diff-preview.tsx)
- [x] **验证入口。** 从会话标题旁打开「验证」，运行项目的测试、类型检查、构建或手动输入的验证命令。显示工作目录、命令、实时输出、退出码和耗时。每次执行保存到原会话并关联所属任务与运行。切换会话时命令继续运行，重启后可从原会话查看结果。停止会结束命令和子进程，重跑沿用原命令与目录并新增一条记录。[验证界面](../src/renderer/src/components/ai/verification-dialog.tsx)
- [x] **暂存与提交。** 在 Git 变更面板按文件或文本区块暂存，再从实时暂存区选择要提交的文件或区块。填写提交信息前可预览所选内容的完整 Git 差异。提交时复核分支和暂存区，成功后显示提交号及分支并刷新清单。其余暂存内容与工作树改动保留，仍可查看任务变更记录和检查点。[Git 提交预览](../src/renderer/src/components/ai/git-commit-dialog.tsx)

验收时使用同时含暂存、未暂存和未跟踪文件的仓库，通过内置工具与命令分别修改代码。复查 diff，撤销一块任务改动，运行测试并提交选中的内容。原有改动和暂存状态应按本次选择保留。

### 3. 安全与可靠性

这一组先解决会造成实际损失或让任务半途而废的问题。[权限门实现](../src/main/agent-host/permissions.ts) · [命令工具](../src/main/agent-host/tools/bash.ts)

- [ ] **命令授权范围。** 现在对任意一条命令选择「总是允许」，保存的规则只有工具名，之后所有命令都不再询问。改为按命令前缀保存规则，例如 `pnpm test`、`git status`。含管道、重定向、命令连接符或子命令替换的命令逐段匹配，任意一段未授权就询问。审批卡和设置页显示规则覆盖的范围。旧的无范围命令规则在升级时停用，并在设置页提示重新授权。
- [ ] **危险命令。** 危险规则先于授权规则和完全访问模式判定，命中后始终询问，只能允许一次。规则补充 `git push --force`、`git reset --hard`、`git clean`、`git checkout -- .`、下载后直接执行的管道、磁盘与分区工具，以及指向项目目录之外的递归删除。完全访问模式的说明写明这一例外。
- [ ] **命令执行。** 停止和超时时结束整棵进程树，Windows 使用 `taskkill /T /F`，其他平台结束进程组。失败时返回给模型的输出与成功时使用同一上限，超长时保留开头和结尾并标明省略的长度。超时上限可由模型在限定范围内指定，超时后的结果写明已运行时长。长期运行的命令（开发服务器、监听模式）转入里程碑 5 的终端。
- [ ] **失败重试。** 模型请求遇到网络错误、限流和服务端错误时自动退避重试，界面显示第几次重试和等待时间，可立即取消。重试用尽后，错误卡显示原因和 `重试` 按钮，重试沿用原任务和已保存的上下文。凭据、额度和模型能力错误不自动重试，给出对应的设置入口。[模型适配](../src/main/agent-host/models.ts)
- [ ] **上下文压缩。** 占用接近模型上下文上限时自动压缩较早的对话，保留原始转录、当前计划、关键文件引用和待解决事项。用量弹层提供手动压缩，`/compact` 可附带保留重点。对话中标出压缩发生的位置，可展开查看摘要。较早的长工具输出优先裁剪，界面仍可查看原文。上下文超限错误提供 `压缩并重试`。

验收时在真实 Git 项目中授权 `pnpm test` 后运行 `pnpm test && git push --force`，应再次询问并标红。启动一个会派生子进程的命令后停止，确认没有残留进程。断网后发送消息，检查自动重试、取消和手动重试。用长会话触发自动压缩后继续任务，确认计划和关键文件仍在上下文中，重启后原始转录完整。

### 4. 工作台结构与反馈

按设计规范调整页面结构，再统一状态和反馈。每个模块对应设计规范迁移清单中的一行或几行。[设计规范](./DESIGN.md) · [应用骨架](../src/renderer/src/App.tsx)

- [ ] **外壳与导航。** 标题栏的四个菜单合并为一个应用菜单。主列顶栏改为 40 px 单行，显示会话标题、项目、分支、一个审查开关和更多菜单。更新工程规范中的骨架描述与实现保持一致。
- [ ] **统一审查面板。** 把文件预览、Git 变更、文件变更三个互斥面板和验证对话框合并为一个页签面板，包含变更、文件和验证。面板可拖动调宽并记住宽度，每个页签保留选中的文件和滚动位置。宽度不足时按设计规范的三档布局收起侧栏或覆盖主列。终端页签随里程碑 5 加入。
- [ ] **首页与项目入口。** 空会话按是否有项目和模型显示不同的首要动作。提供最近项目和起步任务，未选择项目时提示当前在默认工作目录运行。
- [ ] **侧栏状态。** 项目行改为单行并可折叠，悬停时可在该项目新建聊天。会话行显示待审批、运行中、失败、已中断和未读状态，状态来自主进程的运行事件，重启后恢复。
- [ ] **通知与提醒。** 窗口失焦或用户在看其他会话时，待审批、任务完成和失败通过系统通知与任务栏提示告知，点击后回到对应会话。可在设置中关闭。
- [ ] **对话流收敛。** 成功的工具步骤折成一行，命令成功时输出默认折叠，失败时展开。回合结束后活动轨迹折成带耗时和步数的摘要。运行期间计划固定在输入区上方。用量弹层常驻显示本会话累计的 token 与费用。
- [ ] **审批细节。** 审批卡显示工作目录、操作对象和授权范围。文件编辑和写入显示差异预览，MCP 工具显示服务名和格式化参数。多个请求显示序号。从工具步骤可回看审批结果。
- [ ] **消息操作。** 用户消息支持复制、编辑并重发、从此处分叉。助手回合支持复制、重试和回到此处，回到此处会通过任务检查点预览并撤销此后的任务改动。
- [ ] **键盘与主题。** 加入设计规范键盘表中的目标快捷键。用键盘走完打开项目、文件引用、审批、查看差异、撤销、运行验证和提交。验证焦点提示和还原、滚动可达性、亮色与暗色对比、中文与英文长文案，以及缩放后的布局。

验收覆盖 Windows 1100 × 750 和 720 × 480 视口，以亮色、暗色和两种现有语言完成主要流程。在任务运行时切到其他窗口，确认待审批和完成的通知能带回原会话。逐项核对设计规范的提交前自检。

### 5. 上下文与开发效率

- [ ] **计划模式。** 第四种权限模式。Agent 只读取和搜索，产出计划后由用户确认，确认后切换到原权限模式执行。计划可在确认前修改。
- [ ] **搜索与导出。** 按项目索引会话全文，可根据消息、文件名或命令找到对应位置。支持 Markdown 导出。
- [ ] **命令面板与斜杠命令。** 命令面板覆盖设计规范列出的全部动作、项目和设置分区。`/` 菜单与命令面板共用动作定义，增加 `/compact`、`/clear`、`/init`（生成项目指令）、`/review`（审查未提交改动）和 `/diff`。支持用户自定义提示词模板，带参数占位。
- [ ] **附件与拖放。** 支持粘贴、拖放和选择图片，模型选择器显示图像能力。重开图文会话能查看附件，切换到文本模型时清楚提示如何处理已选图片。拖入工作目录内的文件生成 `@` 引用。
- [ ] **交互式终端。** 审查面板增加终端页签，在任务工作目录打开，复用平台 Shell 选择，支持输入、停止和复制输出。Agent 可以把长期运行的命令放到后台，读取其输出并结束它，后台命令在终端页签可见。
- [ ] **联网工具。** 增加读取网页和搜索两个工具，默认需要审批，可按域名授权。结果带来源链接，网页内容按长度裁剪后进入上下文。
- [ ] **指令兼容。** 项目没有 `AGENTS.md` 时读取 `CLAUDE.md`。加载工作文件所在子目录的指令文件，指令来源面板列出全部来源和生效顺序。
- [ ] **回合后验证。** 项目可配置回合结束后自动运行的验证命令。结果记入验证页签，失败时可一键把输出交给 Agent 继续修复。

验收时用有长期转录的项目找回历史操作并继续任务。在计划模式下完成一次「先计划后执行」的修改。在支持图片的真实模型上恢复图文会话。让 Agent 启动开发服务器并在后台读取输出，结束任务后确认进程已清理。

### 6. 并行任务

- [ ] **多会话并行。** 不同项目的会话可以同时运行，同一项目内仍然只运行一项任务。限制同时运行的数量。审批、进度、用量和通知按运行独立显示，侧栏状态位反映每个会话的状态。主进程按会话隔离 Agent 实例、权限规则和检查点。
- [ ] **并行工作树。** 同一项目的任务可以使用独立的 Git worktree 和分支。创建时显示基于的分支，完成后可查看差异并合并或丢弃，在归档或移除前提示剩余变更。
- [ ] **子任务。** Agent 可以把只读的搜索和调研交给子任务执行，主对话只接收结论。子任务的步骤可在轨迹中展开查看，用量计入本会话。

验收时在两个项目中同时运行任务并分别审批、审查，再让同一项目的两个工作树各自修改文件。采样多会话下的空闲内存和退出后的资源释放。

### 7. 模型验收与跨平台发行

- [ ] **真实模型验收。** 至少覆盖一个云端提供方，以及 Ollama 和 LM Studio。记录服务版本和模型 ID，实测模型发现、流式文本、工具调用、停止与失败回显。区分网络、凭据、额度和模型能力问题。
- [ ] **Windows。** 每次发版复验新装、旧版升级、卸载和数据保留，继续使用公开 HTTPS 更新源。完善 Windows 安装包签名。
- [x] **Windows 更新入口。** 「帮助 → 检查更新…」显示检查和下载状态，侧栏设置上方可查看下载进度，下载完成后点击即可安装并重启。
- [ ] **Linux 与 macOS。** 在真实桌面环境验证 Linux AppImage 和 `.deb` 的安装或启动、卸载及升级。生成 macOS DMG，验收签名、公证、凭据存储和更新。各平台覆盖 Shell、路径、原生窗控及文件选择。
- [ ] **诊断与迁移。** 在现有滚动日志上增加可导出的脱敏诊断、事件查看和崩溃记录。升级 Electron 前核对内置 Node 的 pi 兼容性，按需迁移异步 `safeStorage`，验证旧密文可读、密钥服务短暂不可用和并发保存。
- [ ] **性能与回归。** 用固定夹具复测冷启动、流式响应、500 条消息滚动和反复切换会话的内存。沿用 Windows 冷启动到可交互低于 3 秒、文字增量到渲染低于 100 毫秒的目标。

Windows 历史安装版抽样记录为冷启动约 1.27 秒、500 条消息滚动帧间隔 P95 为 18.2 毫秒、120 个文字增量最大渲染延迟 32.3 毫秒。发版时按当次提交复测。

GitHub Actions 在代码推送到 `main` 或更新指向 `main` 的 PR 时执行 Windows 验证。发布相关的手动输入为 `build_test_packages`、`verify_installation`、`prepare_release` 和 `verify_published_update`。[构建与发布工作流](../.github/workflows/windows.yml)

### 8. 定时任务与生态扩展

- [ ] **本地定时任务。** 支持创建、编辑、暂停、删除和立即运行。一次性、每日与每周频率可预览下次执行时间。Pilot 运行期间由主进程在独立任务会话执行，首版采用只读权限，并保留历史结果。
- [ ] **调度恢复。** 验收重启、唤醒、时区和夏令时变化、重复触发和失败重跑。标记错过的执行时段和中断的运行。退出应用后的系统调度单独评估。
- [ ] **钩子。** 在工具调用前后和回合结束时运行用户配置的命令，可用于格式化、检查和拦截。钩子的输出和耗时在轨迹中可见。
- [ ] **扩展包与模板。** 预览 npm 或 Git 来源的 Pi Packages 内容，再选择导入技能、提示词模板和主题。验证更新、停用和自定义数据目录迁移。
- [ ] **多语言。** 在现有中英界面上优先加入繁体中文，再评估日语和韩语。统一稳定翻译键、日期与数字格式，覆盖原生对话框、错误和无障碍标签。
- [ ] **外部资料引用。** 先让外部资料的来源可追踪、可点击定位，再评估检索增强生成。

## 首个日用版验收

完成里程碑 3 和 4 后执行。

1. 打开一个已有用户改动的真实 Git 项目，使用真实模型修复导致测试失败的 bug。任务足够长，至少触发一次上下文压缩。
2. 在任务中审批操作，对测试命令授权一次前缀规则。切到其他窗口，等通知把你带回待审批的会话。切换到另一个项目再切回来，检查原任务状态、草稿、工具步骤与工作目录。
3. 中途断开网络再恢复，确认任务自动重试或可以手动重试并继续。
4. 在审查面板查看本轮和原有的变更，按区块撤销一处任务改动，在验证页签重跑测试并查看退出码与日志。
5. 暂存并提交选中的改动。重启应用后打开同一项目，确认会话、验证结果和 Git 状态仍对应原任务。

## 工程与交付约定

Agent、pi SDK、工具执行和密钥使用留在 Electron 主进程。渲染层通过预加载层的类型化 IPC 消费 `UiAgentEvent`，权限由 `beforeToolCall` 判定。已启用技能与项目指令由主进程组装，模型调用产生的用量事件仍发送累计快照。

会话和历史转录沿用按会话保存的 JSONL。持久化格式变更兼容旧数据，工作区路径校验、审批和撤销以运行绑定的目录为准。依赖版本以 `pnpm-lock.yaml` 和 CI 为准，pi 升级集中在 Agent 主机与适配层。[IPC 契约](../src/shared/contract.ts)

每完成一个独立模块，提交并推送当前分支，在开发完成记录中追加日期、交付内容、提交和验收结果。完成路线图中的事项后更新对应状态。代码走工程规范的八步验证，界面模块额外跑对应的桌面场景并核对设计规范的提交前自检。界面结构或交互规则有变化时，同一个提交里更新设计规范。发布产物记录所用提交和目标平台。[工程操作规范](../AGENTS.md) · [设计规范](./DESIGN.md)
