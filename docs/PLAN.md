# Pilot 开发路线图

Pilot 是基于 pi SDK 的本地 AI 编程桌面客户端。面向开发者的核心流程是打开项目、交代任务、审查和验证代码改动，再将选中的改动提交到 Git。桌面界面负责让当前项目、Agent 正在做的事、待审批的操作和验证结果始终可见。页面结构和交互规则见设计规范。[设计规范](./DESIGN.md)

### 1. 项目与会话恢复

已绑定的会话使用自己的目录。切换会话时，原任务继续使用发起时的目录、模型和权限，运行结束后保存到原会话。[AgentHost 实现](../src/main/agent-host/host.ts)

- [x] **项目入口与会话目录绑定。** 打开本地文件夹后，新聊天沿用项目目录，并在创建会话记录时保存目录关联。会话标题下显示目录，文件搜索、引用预览和工具使用该目录。旧会话保留历史，可手动关联项目。
- [x] **最近项目与会话分组。** 侧栏可在重启后重新打开最近项目，包括还没有会话的目录。会话按项目分组，置顶会话在组内优先显示。旧会话可从「未关联项目」找到并关联到最近项目或另一文件夹。Git 项目在会话标题旁显示当前分支。
- [x] **会话设置。** 按会话保存模型选择、未发送的草稿和权限模式。缺少会话设置时使用全局默认值，也可在输入区选择「跟随全局默认」。首条消息被接受后才创建侧栏会话。发送前的草稿保存在本地，可在重启或重新打开项目后恢复。[首页与草稿](./DESIGN.md#26-首页空会话)
- [x] **运行归属。** 主进程用会话与运行标识关联流式回复、工具结果、审批和停止操作。切回原会话可以查看进度、处理审批或停止。应用同时保留一项活动任务，其他会话可以编辑草稿，尝试发送时会提示任务所在的会话。
- [x] **在途保存与恢复。** 在收到用户消息、完成工具步骤和回合结束时保存转录和运行状态。异常退出后显示「已中断」，可在原工作目录从已保存的上下文继续。续跑保留已记录的工具结果，并拦住已开始执行的相同文件写入、编辑和命令。未保存结果的操作显示为结果未知。
- [x] **项目指令。** 按会话绑定的目录加载项目根目录的指令文件。从主列 `⋯` 菜单的「指令来源」查看路径和生效顺序。发生冲突时，应用指令优先，其后依次是项目指令、会话指令（未设置时用全局个性化）、技能。每次任务重新读取项目指令，子目录规则按目标路径加载。[指令来源](./DESIGN.md#25-主列顶栏)

验收时交替打开两个项目。在流式回复、等待审批和工具运行时切换会话，检查消息、工作目录和请求的归属。停止任务和重启后复查草稿、部分结果与历史数据。

### 2. Git 审查与验证

- [x] **Git 变更。** Agent 执行前记录暂存区、工作树和未跟踪文件的基线。从审查面板的「变更」页签查看内置工具和命令产生的新增、修改、删除与重命名。面板标出已有改动、任务期间的变化和归属不明的混合变更。重新打开会话可查看最近一次任务结束时的清单。[Git 变更](../src/renderer/src/components/ai/git-changes-panel.tsx)
- [x] **差异与撤销。** 在 Git 变更面板展开文件查看逐行差异，点击新版本行号可在 VS Code 定位到工作树中的对应行。打开「任务检查点」，可按文件或区块预览撤销范围。确认时复核当前文件和暂存内容，遇到归属不明、暂存变化或后续编辑时提示冲突并保留文件。已完成的检查点可随会话重开。普通文件夹继续使用已有工具差异与撤销。[Git 差异和撤销预览](../src/renderer/src/components/ai/git-diff-preview.tsx)
- [x] **验证入口。** 在审查面板的「验证」页签运行项目的测试、类型检查、构建或手动输入的验证命令。显示工作目录、命令、实时输出、退出码和耗时。每次执行保存到原会话并关联所属任务与运行。切换会话时命令继续运行，重启后可从原会话查看结果。停止会结束命令和子进程，重跑沿用原命令与目录并新增一条记录。[验证页签](../src/renderer/src/components/ai/verification-panel.tsx)
- [x] **暂存与提交。** 在 Git 变更面板按文件或文本区块暂存，再从实时暂存区选择要提交的文件或区块。填写提交信息前可预览所选内容的完整 Git 差异。提交时复核分支和暂存区，成功后显示提交号及分支并刷新清单。其余暂存内容与工作树改动保留，仍可查看任务变更记录和检查点。[Git 提交预览](../src/renderer/src/components/ai/git-commit-dialog.tsx)

验收时使用同时含暂存、未暂存和未跟踪文件的仓库，通过内置工具与命令分别修改代码。复查 diff，撤销一块任务改动，运行测试并提交选中的内容。原有改动和暂存状态应按本次选择保留。

### 3. 基础稳健性

这一组补上桌面应用的基础保护，出问题时不丢数据，窗口可以恢复。各项互相独立，可以逐个提交。[主进程入口](../src/main/index.ts) · [设置存储](../src/main/settings/index.ts)

- [x] **单实例。** 对同一数据目录再次启动时会聚焦已有窗口，窗口最小化时先还原。后启动的进程在加载设置和会话前退出。Windows 目录联接指向同一实际目录时也会唤醒原窗口。通过 `--user-data-dir` 指定独立目录的验收实例可与日常实例并存。[Windows 回归验证](../scripts/verify-windows.mjs)
- [x] **设置损坏保护。** 设置内容无法解析或结构损坏时，先把原文件另存为带时间戳的备份，再保存默认设置。界面显示备份路径。恢复受阻时保留原文件并暂停保存，恢复文件访问后可重试。会话索引损坏时备份原索引，保留仍有效的条目，再根据转录和草稿文件补回缺失的会话。[设置存储](../src/main/settings/index.ts) · [会话存储](../src/main/agent-host/session-store.ts)
- [x] **界面崩溃恢复。** 组件报错时显示原因及「重新加载」和「查看日志」。渲染进程退出或无响应时，主进程通过原生提示重新加载已有窗口。重载后接回当前会话、主进程中继续运行的任务、草稿和待审批请求。[界面错误边界](../src/renderer/src/components/app-error-boundary.tsx) · [窗口恢复](../src/main/window-recovery.ts)
- [x] **退出确认。** 有任务或验证命令在运行时，关闭窗口、退出和更新重启都先询问。取消后继续运行。确认后停止任务、保存可继续的检查点，结束验证命令并记录已中断，再关闭、退出或安装。Agent 命令的整棵进程树清理见里程碑 4。[退出流程](../src/main/desktop-exit.ts)
- [x] **窗口与布局记忆。** 按数据目录恢复窗口位置、大小和最大化状态，标题栏移出可用工作区时将窗口移到主屏中央。记住侧栏宽度、收起状态和审查面板宽度。[窗口状态](../src/main/window-state.ts) · [布局偏好](../src/renderer/src/lib/preferences.ts)
- [x] **运行期间不休眠。** Agent 任务或验证命令运行时阻止系统自动睡眠，屏幕仍可按系统设置熄灭。等待审批和停止收尾也属于运行期间。最后一项工作完成、失败或停止后解除。[睡眠阻止](../src/main/sleep-blocker.ts)

验收时连续启动两次，确认只有一个窗口并被带到前台。手工写坏设置文件后启动，确认界面显示的备份保留原文件内容。模拟备份失败，确认保存被拦截。写坏会话索引后重启，从侧栏打开已有聊天和草稿。在任务运行时结束渲染进程，确认窗口恢复后任务仍在进行。运行中按 `Ctrl+Q`，确认出现询问，取消后任务继续，确认后没有残留进程。移动并调整窗口和侧栏后重启，确认恢复到原来的位置和宽度。同时运行 Agent 任务和验证命令，确认最后一项工作结束后解除睡眠阻止。

### 4. 安全与可靠性

这一组先解决会造成实际损失或让任务半途而废的问题。[权限门实现](../src/main/agent-host/permissions.ts) · [命令工具](../src/main/agent-host/tools/bash.ts)

- [x] **命令授权范围。** 确认模式按 Shell 和完整参数边界匹配 `pnpm test`、`git status` 等前缀。管道、连接命令和可解析的子命令替换需要每段命中授权。未匹配、重定向和无法可靠解析的命令逐次审批。审批卡显示完整命令与工作目录，菜单显示长期授权的实际范围。权限设置显示工具、规则范围和撤销入口。旧的无范围命令规则已停用，设置页提示重新授权。[设计规范](./DESIGN.md#29-审批卡)
- [x] **危险命令。** 权限门先检查 PowerShell 和 Git Bash 中能识别的危险操作，再判断命令授权和完全访问模式。覆盖 `git push --force`、`git reset --hard`、`git clean`、`git checkout -- .`、下载后直接执行的管道、磁盘与分区操作，以及目标在项目外或无法确认范围的递归删除。命中规则时显示原因，只能本次允许或拒绝。完全访问模式的说明已同步。[危险规则](../src/main/agent-host/command-danger.ts)
- [x] **运行对象拆分。** `AgentRun` 管理一次运行的生命周期、审批、插话队列、检查点、中止和 Git 任务快照。`AgentHost` 负责会话选择、Agent 缓存和工作区审查入口。切换会话时审批与队列随原运行保留，退出等待运行保存检查点和清理，续跑分配新运行 ID 并识别检查点中已经启动过的操作。命令执行和失败重试使用这个运行对象，里程碑 7 在此基础上引入多会话调度。[AgentRun 实现](../src/main/agent-host/run.ts) · [AgentHost 实现](../src/main/agent-host/host.ts)
- [x] **命令执行。** 停止和超时时清理受控命令进程树，Windows 使用 `taskkill /T /F`，其他平台结束进程组。成功与失败的命令输出都以 100,000 字符为上限，超长时保留首尾并标出省略的字符数。模型可通过 `timeoutSec` 指定 1–300 秒的超时，默认 60 秒，超时结果包含已运行时长。Windows 上 Shell 已退出且输出管道迟迟未关闭时，工具报告清理未确认。开发服务器和监听模式等后台命令随里程碑 6 的终端交付。[命令工具](../src/main/agent-host/tools/bash.ts)

验收时在真实 Git 项目中授权 `pnpm test` 后运行 `pnpm test && git push --force`，应再次询问并标红。启动一个会派生子进程的命令后停止，确认没有残留进程。断网后发送消息，检查自动重试、取消和手动重试。把一个兼容端点模型的上下文长度改小，确认用量百分比和压缩时机随之变化。启用十个技能后发送消息，确认请求里只有技能清单，模型用到某个技能时才读取正文，并能运行技能目录里的脚本。用长会话触发自动压缩后继续任务，确认计划和关键文件仍在上下文中，重启后原始转录完整。

### 7. 并行任务

- [ ] **多会话并行。** 不同项目的会话可以同时运行，同一项目内仍然只运行一项任务。限制同时运行的数量。审批、进度、用量和通知按运行独立显示，侧栏状态位反映每个会话的状态。主进程按会话隔离 Agent 实例、权限规则和检查点。
- [ ] **并行工作树。** 同一项目的任务可以使用独立的 Git worktree 和分支。创建时显示基于的分支，完成后可查看差异并合并或丢弃，在归档或移除前提示剩余变更。
- [ ] **子任务。** Agent 可以把只读的搜索和调研交给子任务执行，主对话只接收结论。子任务的步骤可在轨迹中展开查看，用量计入本会话。

验收时在两个项目中同时运行任务并分别审批、审查，再让同一项目的两个工作树各自修改文件。采样多会话下的空闲内存和退出后的资源释放。

### 8. 模型验收与跨平台发行

- [ ] **真实模型验收。** 至少覆盖一个云端提供方，以及 Ollama 和 LM Studio。记录服务版本和模型 ID，实测模型发现、流式文本、工具调用、停止与失败回显。区分网络、凭据、额度和模型能力问题。
- [ ] **Windows。** 每次发版复验新装、旧版升级、卸载和数据保留，继续使用公开 HTTPS 更新源。完善 Windows 安装包签名。
- [x] **Windows 更新入口。** 「帮助 → 检查更新…」显示检查和下载状态，侧栏设置上方可查看下载进度，下载完成后点击即可安装并重启。
- [x] **Linux 更新入口。** AppImage 和 Debian 安装包共用「检查更新…」，下载时校验对应文件。AppImage 可保留原路径替换并重启，Debian 安装包提供下载位置，由系统包管理器安装。发行流程包含 `latest-linux.yml`，CI 用两个打包版本复核检查、下载和升级。[Linux 更新验收](../scripts/verify-linux-update.mjs)
- [ ] **更新策略。** 现在只在启动后检查一次更新，发现新版后自动下载。改为运行期间定期检查，并在设置「关于」里提供自动下载开关。关闭后发现新版只提示，由用户决定何时下载。[更新实现](../src/main/updater.ts)
- [ ] **Linux 与 macOS。** 在真实桌面环境验证 Linux AppImage 和 `.deb` 的安装或启动、卸载及升级。生成 macOS DMG，验收签名、公证、凭据存储和更新。各平台覆盖 Shell、路径、原生窗控及文件选择。
- [ ] **诊断与迁移。** 在现有滚动日志上增加可导出的脱敏诊断、事件查看和崩溃记录。升级 Electron 前核对内置 Node 的 pi 兼容性，按需迁移异步 `safeStorage`，验证旧密文可读、密钥服务短暂不可用和并发保存。
- [ ] **持久化格式版本。** 设置文件和会话记录写入格式版本号，读取时按版本迁移，没有版本号的旧数据按初始版本处理。遇到比当前应用更新的版本时不覆盖原文件，提示升级应用。
- [ ] **数据备份与恢复。** 设置「存储与诊断」可把会话、设置、技能和授权规则导出为一个备份包，在新机器或重装后导入。导入前显示将覆盖的内容。密钥由本机的系统密钥服务加密，换机后无法解密，导入后提示重新填写。
- [ ] **性能与回归。** 用固定夹具复测冷启动、流式响应、500 条消息滚动和反复切换会话的内存。沿用 Windows 冷启动到可交互低于 3 秒、文字增量到渲染低于 100 毫秒的目标。

Windows 历史安装版抽样记录为冷启动约 1.27 秒、500 条消息滚动帧间隔 P95 为 18.2 毫秒、120 个文字增量最大渲染延迟 32.3 毫秒。发版时按当次提交复测。

GitHub Actions 在代码推送到 `main` 或更新指向 `main` 的 PR 时执行 Windows 验证。发布相关的手动输入为 `build_test_packages`、`verify_installation`、`prepare_release` 和 `verify_published_update`。[构建与发布工作流](../.github/workflows/windows.yml)

### 9. 定时任务与生态扩展

- [ ] **本地定时任务。** 支持创建、编辑、暂停、删除和立即运行。一次性、每日与每周频率可预览下次执行时间。Pilot 运行期间由主进程在独立任务会话执行，首版采用只读权限，并保留历史结果。
- [ ] **调度恢复。** 验收重启、唤醒、时区和夏令时变化、重复触发和失败重跑。标记错过的执行时段和中断的运行。退出应用后的系统调度单独评估。
- [ ] **钩子。** 在工具调用前后和回合结束时运行用户配置的命令，可用于格式化、检查和拦截。钩子的输出和耗时在轨迹中可见。
- [ ] **用量统计。** 按天、项目和模型汇总 token 与费用，数据来自已保存的会话用量。单价依赖里程碑 4 的模型能力配置。
- [ ] **托盘与全局快捷键。** 关闭窗口后可留在系统托盘继续运行任务，全局快捷键唤起窗口并聚焦输入框。两项都可在设置中关闭。
- [ ] **页面预览。** 审查面板增加预览页签，打开后台开发服务器的本地地址，可把页面截图和控制台错误交给 Agent。
- [ ] **远程与容器项目。** 评估在 WSL、SSH 主机或容器里打开项目并执行命令，先做 WSL。
- [ ] **多语言。** 在现有中英界面上优先加入繁体中文，再评估日语和韩语。统一稳定翻译键、日期与数字格式，覆盖原生对话框、错误和无障碍标签。
- [ ] **外部资料引用。** 先让外部资料的来源可追踪、可点击定位，再评估检索增强生成。

## 首个日用版验收

完成里程碑 3、4 和 5 后执行。

1. 打开一个已有用户改动的真实 Git 项目，使用真实模型修复导致测试失败的 bug。任务足够长，至少触发一次上下文压缩。
2. 在任务中审批操作，对测试命令授权一次前缀规则。切到其他窗口，等通知把你带回待审批的会话。切换到另一个项目再切回来，检查原任务状态、草稿、工具步骤与工作目录。
3. 中途断开网络再恢复，确认任务自动重试或可以手动重试并继续。
4. 在审查面板查看本轮和原有的变更，按区块撤销一处任务改动，在验证页签重跑测试并查看退出码与日志。
5. 暂存并提交选中的改动。重启应用后打开同一项目，确认会话、验证结果和 Git 状态仍对应原任务。
6. 任务运行时再次启动 Pilot，应回到已打开的窗口。此时关闭窗口，应先询问是否停止任务。

## 工程与交付约定

Agent、pi SDK、工具执行和密钥使用留在 Electron 主进程。渲染层通过预加载层的类型化 IPC 消费 `UiAgentEvent`，权限由 `beforeToolCall` 判定。已启用技能与项目指令由主进程组装，模型调用产生的用量事件仍发送累计快照。

会话和历史转录沿用按会话保存的 JSONL。持久化格式变更兼容旧数据，工作区路径校验、审批和撤销以运行绑定的目录为准。依赖版本以 `pnpm-lock.yaml` 和 CI 为准，pi 升级集中在 Agent 主机与适配层。[IPC 契约](../src/shared/contract.ts)

每完成一个独立模块，提交并推送当前分支，在开发完成记录中追加日期、交付内容、提交和验收结果。完成路线图中的事项后更新清单，整个里程碑完成时同步更新「开发顺序」的状态。代码走工程规范的八步验证，界面模块额外跑对应的桌面场景并核对设计规范的提交前自检。界面结构或交互规则有变化时，同一个提交里更新设计规范。发布产物记录所用提交和目标平台。[工程操作规范](../AGENTS.md) · [设计规范](./DESIGN.md)
