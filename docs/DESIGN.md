# Pilot 设计规范

本文定义 Pilot 的页面结构、状态表达、视觉与交互规则。新增或修改界面前先对照本文，界面与本文不一致时，以本文为目标修正代码，或先改本文再改代码。开发顺序见路线图，工程约束见工程规范。[开发路线图](./PLAN.md) · [工程操作规范](../AGENTS.md)

标注「现状」的内容描述 `v0.3.0` 的实现，标注「目标」的内容是后续模块要达到的结构。两者的差距汇总在[迁移清单](#迁移清单)。

## 1. 设计原则

1. **对话是主线，审查是副线。** 主列只承载任务的来龙去脉，差异、验证输出和终端放进右侧审查面板。任何时候主列都能独立读懂任务进展。
2. **状态不靠猜。** 当前项目、分支、权限模式、Agent 在做什么、是否在等用户，都在固定位置可见。离开当前会话或窗口后，状态跟到侧栏和系统通知。
3. **默认收敛，按需展开。** 成功的步骤折成一行，失败和待处理的内容自动展开。用户不需要滚过一屏命令输出才能看到结论。
4. **每个失败都带下一步。** 错误处显示实际原因和可执行的动作，例如重试、换模型、打开设置或查看日志。
5. **放权要看得清范围。** 审批卡说明操作对象、所在目录和授权会覆盖什么。风险用橙色提醒，破坏性操作用红色并始终询问。
6. **键盘可以走完主流程。** 打开项目、发送、审批、看差异、运行验证和提交都有键盘路径，焦点在浮层关闭后回到原处。

## 2. 页面结构

### 2.1 窗口骨架

窗口分两层。外层是窗框色 `bg-window-frame`，承载标题栏和导航栏。内层是一张圆角工作卡片，承载侧栏、主列和审查面板。标题栏属于窗框，和导航栏同色相连，卡片内不再出现横跨多列的横条。[应用骨架](../src/renderer/src/App.tsx)

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 标题栏 38px（窗框色，可拖拽）  ≡  ←  →  ▯             原生窗口按钮    │
├────┬─────────────────────────────────────────────────────────────────┤
│ 导 │ ┌─────────────┬──────────────────────────┬────────────────────┐ │
│ 航 │ │ 侧栏        │ 主列顶栏 40px            │ 审查面板页签 40px  │ │
│ 栏 │ │ 项目与会话  ├──────────────────────────┼────────────────────┤ │
│ 52 │ │ 220–520px   │ 对话流                   │ 变更 / 文件 /      │ │
│ px │ │ 默认 262px  │ 内容列最宽 48rem，居中   │ 验证 / 终端        │ │
│    │ │             ├──────────────────────────┤ 可拖宽            │ │
│    │ │             │ 输入坞                   │                    │ │
│    │ └─────────────┴──────────────────────────┴────────────────────┘ │
└────┴─────────────────────────────────────────────────────────────────┘
```

### 2.2 区域职责

| 区域 | 尺寸 | 放什么 | 不放什么 |
| --- | --- | --- | --- |
| 标题栏 | 高 38px | 应用菜单 `≡`、后退、前进、侧栏开关，其余为拖拽区 | 会话标题、项目操作、状态文字 |
| 导航栏 | 宽 52px | 首页、搜索、新聊天（侧栏收起时）、更新、设置 | 会话列表、项目级操作 |
| 侧栏 | 220–520px，默认 262px | 打开项目、新聊天、项目分组与会话、未关联与已归档。设置视图下换成设置导航 | 当前会话的工具和审查入口 |
| 主列顶栏 | 高 40px，单行 | 会话标题、项目名、分支、审查面板开关、更多菜单 | 两行信息、三个以上并列按钮 |
| 对话流 | 内容列最宽 48rem | 用户消息、助手回合、错误与中断卡 | 完整差异、长命令输出、表单 |
| 输入坞 | 与内容列同宽，贴底 | 当前计划条、排队消息、审批卡或输入框 | 与本次输入无关的全局设置 |
| 审查面板 | 最小 360px，默认占卡片内剩余宽度的一半 | 变更、文件、验证、终端四个页签 | 对话内容、设置 |
| 设置视图 | 复用主列，内容列最宽 48rem | 侧栏导航对应的设置分区 | 审查面板 |

### 2.3 标题栏与应用菜单

- 目标：`文件 / 编辑 / 视图 / 帮助` 四个菜单合并为一个 `≡` 应用菜单，分组依次为会话（新聊天、打开项目、搜索）、视图（侧栏、审查面板、缩放、全屏）、编辑、帮助（检查更新、关于）、退出。标题栏只留 `≡ ← → ▯` 四个控件。[标题栏实现](../src/renderer/src/components/ai/top-bar.tsx)
- 菜单项右侧显示快捷键。退出使用红色。
- 标题栏控件统一用 `.app-titlebar-control`，高 28px，图标 16px。

### 2.4 侧栏

- **顶部操作。** `打开项目` 和 `新聊天` 两个按钮。新聊天默认落在当前项目。
- **项目分组。** 项目行单行显示文件夹名，完整路径放进 `title`，同名项目才在名称后用灰阶补上一级目录。项目行可折叠，折叠状态本地保存。悬停时右侧出现「在此项目新建聊天」和更多菜单。
- **会话行。** 单行标题，左侧 8px 状态位，右侧相对时间，悬停时时间换成置顶和归档按钮。当前会话用 `bg-sidebar-accent` 底色表示，不加粗、不加 ✓。
- **状态位。** 每行只显示优先级最高的一种，定义见[状态模型](#3-状态模型)。
- **排序。** 组内置顶在前，其余按最近活动时间。项目按最近活动时间。
- **收起。** 宽窗下由用户控制。打开审查面板后宽度不足时自动收起，关闭面板后恢复用户原先的选择。

### 2.5 主列顶栏

单行，从左到右：

1. 会话标题，可点击重命名，超长截断。
2. 项目名芯片，点击打开项目切换菜单。未关联项目时显示橙色的 `选择项目`，提示当前使用默认工作目录。
3. Git 分支，灰阶小字，无 Git 时不显示。
4. 右侧 `审查` 开关，带变更文件数角标和最近一次验证的状态点，点击打开上次使用的页签。
5. `⋯` 更多菜单，收纳指令来源、关联项目、会话指令、导出、归档。

「验证」「Git 变更」「指令」不再作为三个并列按钮出现在顶栏。

### 2.6 首页（空会话）

空会话是用户每天的入口，按是否有项目分两种：

- **已有项目。** 标题下方直接是输入框，输入框上方一行显示当前项目和分支，可切换。输入框下方给 3–4 个起步任务，例如「梳理这个项目的结构」「运行测试并修复失败项」「审查未提交的改动」，点击后填入草稿。
- **没有项目。** 首要动作是 `打开项目`，其下列出最近项目，每项两行显示名称和路径。输入框仍可用，旁边用橙色提示当前在默认工作目录运行。
- **没有可用模型。** 首要动作换成 `配置模型`，其余入口保留。

### 2.7 对话流

- **用户消息。** 右对齐气泡，悬停显示操作条，包含复制、编辑并重发、从此处分叉。
- **助手回合。** 依次是活动轨迹、正文、文件变更卡。回合结束后，活动轨迹整体折成一行摘要，格式为「已处理 2 分 13 秒 · 12 步」，点击展开。正文下方悬停显示复制、重试、回到此处（撤销此后的任务改动）。
- **工具步骤。** 运行中显示当前步骤并保持展开。成功后折成一行，包含动作、对象和耗时。失败时展开并显示错误。命令成功时输出默认折叠，命令失败时展开。[工具轨迹](../src/renderer/src/components/ai/tool-trace.tsx)
- **计划。** 运行期间固定在输入坞上方，显示当前步骤和进度。回合结束后，最终计划留在该回合的轨迹里。
- **错误卡。** 一句话原因、可展开的原始信息和动作按钮。动作按错误类型给出，例如网络和限流给 `重试`，凭据给 `打开模型设置`，上下文超限给 `压缩并重试`。
- **中断卡。** 说明中断发生的位置，提供 `继续任务`。
- **回到最新。** 用户上翻阅读时停止自动吸底，右下角出现回到最新的按钮。轮次刻度轨钉在内容列左侧留白内，留白不足时整体隐藏。

### 2.8 输入坞

从上到下最多三层，全部与内容列对齐：

1. **计划条。** 仅运行期间出现，单行，可展开全部步骤。
2. **排队条。** 有插话排队时出现，显示条数，可清空。
3. **输入框或审批卡。** 等待审批时审批卡替换输入框，草稿保留，处理后恢复草稿和焦点。

输入框底部工具行，左侧是 `+` 附件、权限模式、上下文用量，右侧是模型与强度、发送或停止。[输入框实现](../src/renderer/src/components/ai/composer.tsx)

- 上下文用量弹层始终显示本会话累计的 token 与费用，占用超过 80% 时转橙色并提供 `压缩上下文`。
- 拖入工作目录内的文件生成 `@` 引用芯片。拖入或粘贴图片生成附件缩略图。
- 运行中占位文字说明此时发送是插话。

### 2.9 审批卡

- 标题是一句话操作，例如「运行命令」「编辑 src/app.ts」。下方显示工作目录。[审批卡实现](../src/renderer/src/components/ai/permission-card.tsx)
- 内容区按工具类型展示。命令显示完整命令，可滚动。文件编辑和写入显示差异预览。MCP 工具显示服务名和格式化后的参数。
- 主按钮 `允许一次`，次按钮 `拒绝`。`⋯` 菜单中的长期授权必须写明范围，例如「本会话允许 `pnpm test` 开头的命令」「始终允许编辑 src/ 下的文件」。命令类授权按命令前缀生效，不提供「允许所有命令」。
- 命中危险规则的命令使用红色标题和原因说明，只提供允许一次和拒绝。
- 多个请求按顺序处理，卡片角上显示「1 / 3」。

### 2.10 审查面板

右侧只有一个面板，用页签切换，取代现在三个互斥的面板和验证对话框。[Git 变更面板](../src/renderer/src/components/ai/git-changes-panel.tsx) · [验证界面](../src/renderer/src/components/ai/verification-dialog.tsx)

| 页签 | 内容 | 角标 |
| --- | --- | --- |
| 变更 | Git 项目显示暂存、未暂存、未跟踪和任务检查点。普通文件夹显示工具产生的文件差异。提交入口在页签底部 | 变更文件数 |
| 文件 | 从对话中的链接或 `@` 引用打开的文件预览，带行号定位 | 无 |
| 验证 | 测试、类型检查、构建和自定义命令，运行历史与输出 | 运行中转圈，最近一次失败显示红点 |
| 终端 | 任务工作目录下的交互式终端 | 有进程运行时显示绿点 |

- 页签栏高 40px，与主列顶栏对齐。右端是关闭按钮。
- 面板左缘可拖动调宽，宽度本地保存。主列不小于 21rem。
- 每个页签记住自己的选中文件和滚动位置，切换页签或收起再打开后恢复。
- 需要用户确认范围的操作使用对话框，例如提交预览和撤销预览。只读内容都留在面板里。

### 2.11 命令面板

`Ctrl+K` 打开，是所有动作的统一入口。分组为操作、项目、会话、设置分区。操作至少包含新聊天、打开项目、切换权限模式、切换模型、打开审查面板各页签、运行验证、压缩上下文、切换主题和语言。会话支持全文匹配，结果显示命中片段。[命令面板实现](../src/renderer/src/components/ai/command-palette.tsx)

输入框的 `/` 菜单与命令面板共用同一份动作定义，另外包含技能和提示词模板。

### 2.12 设置视图

- 侧栏换成设置导航，分为应用（常规、模型、个性化、数据）和集成（技能、MCP 服务、导入）。顶部有返回对话的入口。
- 每个分区由若干 `section` 组成，小标题 `text-sm font-medium`，内容用 `.settings-list` 和 `.settings-row`。
- 行内左侧是标题和灰阶说明，右侧是控件。选择类设置即时生效。需要校验的表单在分区底部显示保存按钮和结果。
- 权限规则列表显示工具、范围（命令前缀或路径前缀）和撤销按钮。

### 2.13 窗口宽度适配

验收视口为 1100 × 750 和 720 × 480。

| 窗口宽度 | 布局 |
| --- | --- |
| ≥ 1100px | 侧栏、主列、审查面板三列并排 |
| 900–1099px | 打开审查面板时自动收起侧栏，主列与面板并排 |
| < 900px | 审查面板覆盖主列，页签栏左端提供返回对话的按钮。侧栏以覆盖层展开 |

切换布局时保留所选文件、页签和滚动位置。

## 3. 状态模型

同一种状态在所有位置使用同一组颜色、图标和文案。

| 状态 | 颜色 | 侧栏状态位 | 主列与输入坞 | 窗口外 |
| --- | --- | --- | --- | --- |
| 待审批 | 橙 | 橙色实心点 | 审批卡替换输入框 | 系统通知，任务栏闪烁 |
| 运行中 | emerald | 绿色转圈 | 当前步骤、计划条、停止按钮 | 无 |
| 停止中 | 灰阶 | 灰色转圈 | 停止按钮禁用并显示「正在停止」 | 无 |
| 失败 | 红 | 红色实心点 | 错误卡和下一步动作 | 系统通知 |
| 已中断 | 灰阶 | 灰色空心点 | 中断卡和继续任务 | 无 |
| 已完成未读 | 主色 | 主色实心点 | 无 | 窗口不在前台时发系统通知 |
| 空闲 | 无 | 无 | 发送按钮 | 无 |

- 状态位的优先级从上到下递减，每行只显示一种。
- 系统通知只在窗口失焦或用户正在看别的会话时发送，点击后回到对应会话。可在设置中关闭。
- 验证命令的状态独立于 Agent 运行，显示在审查开关的状态点和验证页签上。

## 4. 视觉规范

### 4.1 颜色

颜色只用主题变量，不在组件里写色值。[主题变量](../src/renderer/src/assets/main.css)

| 用途 | 变量或类名 |
| --- | --- |
| 窗框、标题栏、导航栏 | `bg-window-frame` |
| 侧栏 | `bg-sidebar`，文字 `text-sidebar-foreground`，当前项 `bg-sidebar-accent` |
| 主列与卡片 | `bg-background`，文字 `text-foreground` |
| 对话中的工作区链接与引用芯片 | `var(--workspace-reference)` |
| 次级文字 | `text-muted-foreground` |
| 分隔线 | `border-border`，列内弱分隔用 `border-border/65` |

语义色分四级：

- **红 `destructive`。** 破坏性动作和真实危险，例如拒绝、删除、错误、危险命令。
- **橙 `text-amber-600 dark:text-amber-400`。** 需要用户留意但不具破坏性，例如完全访问模式、待审批、上下文将满、未选择项目。
- **emerald。** 运行中、成功、流式光标。
- **灰阶。** 次级文字和常态。

带语义色的图标，同一行的标题文字跟随同色，说明行保持灰阶。差异的增删行使用绿色和红色背景，同时保留 `+` 和 `-` 符号。

### 4.2 字号与字重

| 层级 | 规格 | 用途 |
| --- | --- | --- |
| 页面标题 | `clamp(1.375rem, 2.5vw, 1.75rem)`，`font-semibold` | 首页标题、设置分区标题 |
| 正文 | 14px（`text-sm`） | 消息正文、表单、按钮 |
| 界面文字 | 13px | 顶栏标题、侧栏行、菜单、标题栏 |
| 辅助文字 | 12px（`text-xs`），`text-muted-foreground` | 说明行、时间、路径、角标 |
| 代码 | 等宽，13px | 命令、差异、终端、路径 |

字重只用 `font-normal`、`font-medium` 和 `font-semibold`。`font-medium` 用于小标题和当前标题，不用加粗表示选中。

### 4.3 尺寸与间距

- 间距取 4px 的倍数。行内图标与文字间距 6–8px，列表行内边距 8–12px，分区间距 28px。
- 圆角以 `--radius`（10px）为基准。工作卡片 `rounded-xl`，卡片与对话框 `rounded-lg` 及以上，按钮和输入 `rounded-md`，芯片 `rounded-sm` 或全圆。
- 固定高度：标题栏 38px，主列顶栏与面板页签栏 40px，侧栏会话行 30–32px，标题栏控件 28px，小按钮 28px，默认按钮 32px。
- 图标使用 lucide，界面内 16px，辅助信息旁 12–14px，描边 1.7 左右。纯图标按钮必须有 `aria-label` 和 `title`。

### 4.4 动效

- 展开、收起和面板滑入 150–200ms，使用缓出曲线。拖动调宽期间关闭宽度过渡。
- 流式输出不加逐字动画。转圈只用于确实在等待的状态。
- 遵循系统的减少动态效果设置。

## 5. 组件规则

### 5.1 选哪种容器

| 场景 | 容器 |
| --- | --- |
| 持续查看、与对话并行的内容 | 审查面板页签 |
| 需要用户确认范围或不可撤销的操作 | 对话框 |
| 少量选项或一次性的设置 | 下拉菜单或弹出层 |
| 阻塞当前任务、必须处理的请求 | 输入坞内的卡片 |
| 操作结果反馈 | 就地显示在触发位置旁。跨区域的结果用可自动消失的提示条 |

### 5.2 菜单与列表

- 次级信息使用上下结构。主标题一行，说明另起一行，`text-xs text-muted-foreground`。不把说明用「·」挤进标题行。
- 带说明行的条目用 `items-start`，图标 `mt-0.5` 与首行对齐，内容块 `flex-col gap-0.5`。
- 选中项在右侧显示 `CheckIcon`，不用加粗或变色表示。
- 下拉弹层宽度随内容自适应，最小 `min-w-40`，不使用 `w-(--anchor-width)` 锁定锚宽。
- 路径过长时保留末尾，用 `[direction:rtl]` 配合 `<bdi dir="ltr">` 截断前部。
- `DropdownMenuLabel` 放在 `DropdownMenuGroup` 内。自定义触发器用 `render={<button />}`。

### 5.3 按钮

- 每个区域最多一个主按钮。次要动作用 `outline`，行内和工具行动作用 `ghost`，破坏性动作用 `destructive`，并在不可撤销时二次确认。
- 按钮文字是动词短语，例如「允许一次」「运行测试」「提交 3 个文件」。打开对话框或系统选择器的入口以「…」结尾。
- 进行中的按钮禁用并改为进行时文案，例如「保存中…」。

### 5.4 覆盖物

刻度轨、小地图等覆盖物钉在内容列的留白内，用 ResizeObserver 测量主列宽度后定位。留白不足时整体隐藏，不遮挡正文。

### 5.5 空态、加载与错误

- 空态说明这里会出现什么，并给出一个动作。
- 加载超过 300ms 才显示转圈或骨架。列表刷新时保留旧内容。
- 错误就地显示，红色文字加 `role="alert"`，内容经 `localizeError` 本地化。

## 7. 文案与多语言

- 界面文案用 `t("中文原文", locale)`，中文原文即翻译键。新增文案同时补英文词条。
- 用完整的短句，直接说明对象和结果。不使用感叹号，不用「请稍候」之类不含信息的提示。
- 中文与英文、数字之间留一个空格。省略号用「…」。
- 布局按英文长度验收，按钮和页签在英文下不换行、不截断关键词。
- 时间用相对时间，悬停显示完整时间。耗时写成「2 分 13 秒」或 `2m 13s`。

## 8. 可访问性

- 文字与背景的对比度不低于 4.5:1，辅助文字和图标不低于 3:1，亮色与暗色都要检查。
- 状态不只靠颜色表达，同时使用图标形状或文字。
- 流式内容区域使用礼貌播报，审批和错误使用 `role="alert"`。
- 界面缩放到 150% 时主流程可用。
