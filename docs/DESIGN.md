# Pilot 设计规范

本文定义 Pilot 的页面结构、状态表达、视觉与交互规则。新增或修改界面前先对照本文，界面与本文不一致时，以本文为目标修正代码，或先改本文再改代码。开发顺序见路线图，工程约束见工程规范。[开发路线图](./PLAN.md) · [工程操作规范](../AGENTS.md)

标注「目标」的内容随对应模块交付。[迁移清单](#迁移清单)

## 1. 设计原则

1. **对话是主线，审查是副线。** 主列只承载任务的来龙去脉，差异、验证输出和终端放进右侧审查面板。任何时候主列都能独立读懂任务进展。
2. **状态不靠猜。** 当前项目、分支、权限模式、Agent 在做什么、是否在等用户，都在固定位置可见。离开当前会话或窗口后，状态跟到侧栏和系统通知。
3. **默认收敛，按需展开。** 成功的步骤折成一行，失败和待处理的内容自动展开。用户不需要滚过一屏命令输出才能看到结论。
4. **每个失败都带下一步。** 错误处显示实际原因和可执行的动作，例如重试、换模型、打开设置或查看日志。
5. **放权要看得清范围。** 审批卡说明操作对象、所在目录和授权会覆盖什么。风险用橙色提醒，破坏性操作用红色并始终询问。
6. **键盘可以走完主流程。** 打开项目、发送、审批、看差异、运行验证和提交都有键盘路径，焦点在浮层关闭后回到原处。

## 2. 页面结构

### 2.1 窗口骨架

窗口分两层。外层是窗框色 `bg-window-frame`，承载标题栏和导航栏。内层是一张圆角工作卡片，承载侧栏、主列和审查面板。标题栏属于窗框，和导航栏同色相连，卡片内不再出现横跨多列的横条。[应用骨架](../src/renderer/src/App.tsx)

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 标题栏 38px（窗框色，可拖拽）  ≡  ←  →  ▯             原生窗口按钮    │
├────┬─────────────────────────────────────────────────────────────────┤
│ 导 │ ┌─────────────┬──────────────────────────┬────────────────────┐ │
│ 航 │ │ 侧栏        │ 主列顶栏 40px            │ 审查面板页签 40px  │ │
│ 栏 │ │ 项目与会话  ├──────────────────────────┼────────────────────┤ │
│ 52 │ │ 220–520px   │ 对话流                   │ 变更 / 文件 /      │ │
│ px │ │ 默认 262px  │ 内容列最宽 48rem，居中   │ 验证               │ │
│    │ │             ├──────────────────────────┤ 可拖宽            │ │
│    │ │             │ 输入坞                   │                    │ │
│    │ └─────────────┴──────────────────────────┴────────────────────┘ │
└────┴─────────────────────────────────────────────────────────────────┘
```

### 2.2 区域职责

| 区域 | 尺寸 | 放什么 | 不放什么 |
| --- | --- | --- | --- |
| 标题栏 | 高 38px | 应用菜单 `≡`、后退、前进、侧栏开关，其余为拖拽区 | 会话标题、项目操作、状态文字 |
| 导航栏 | 宽 52px | 首页、搜索、新聊天（侧栏收起时）、更新、设置 | 会话列表、项目级操作 |
| 侧栏 | 220–520px，默认 262px | 打开项目、新聊天、项目分组与会话、未关联与已归档。设置视图下换成设置导航 | 当前会话的工具和审查入口 |
| 主列顶栏 | 高 40px，单行 | 会话标题、项目名、分支、审查面板开关、更多菜单 | 两行信息、三个以上并列按钮 |
| 对话流 | 内容列最宽 48rem | 用户消息、助手回合、错误与中断卡、当前会话查找 | 完整差异、长命令输出、表单 |
| 输入坞 | 与内容列同宽，贴底 | 当前计划条、排队消息、审批卡、计划审阅卡或输入框 | 与本次输入无关的全局设置 |
| 审查面板 | 最小 360px，默认占侧栏以外剩余宽度的一半 | 变更、文件、验证三个页签 | 对话内容、设置 |
| 设置视图 | 复用主列，内容列最宽 48rem | 侧栏导航对应的设置分区 | 审查面板 |

### 2.3 标题栏与应用菜单

- 标题栏只留 `≡ ← → ▯` 四个控件。`≡` 是唯一的应用菜单，分组依次为会话（新聊天、打开项目、搜索）、`视图` 子菜单（侧栏、缩放、全屏、重新加载）与 `编辑` 子菜单、应用（设置、检查更新、关于）、窗口（关闭窗口、退出）。[标题栏实现](../src/renderer/src/components/ai/top-bar.tsx)
- `视图` 子菜单提供审查面板开关，以及变更和验证页签的快捷键入口。
- `编辑` 子菜单提供「在当前会话中查找」，已保存的会话可用。
- 菜单项右侧显示快捷键。退出使用红色。
- 标题栏控件统一用 `.app-titlebar-control`，高 28px，图标 16px。
- 使用同一数据目录再次启动 Pilot 时，应用会把已有主窗口带到前台。如果窗口已最小化，会先还原。独立数据目录可以各自打开窗口。[主进程入口](../src/main/index.ts)
- 重启后恢复该数据目录的窗口位置、大小和最大化状态。最大化时同时记住还原后的窗口位置和大小。显示器工作区变化后，按可用区域调整窗口。原位置的标题栏无法操作时，将窗口移到主屏中央。[窗口状态](../src/main/window-state.ts)
- 有 Agent 任务或验证命令在运行时，关闭窗口、退出和更新重启都会显示原生确认框，默认选中「取消」。确认后等待任务和验证命令停止并保存状态，再关闭、退出或启动安装。重开会话后可继续被中断的 Agent 任务。[退出流程](../src/main/desktop-exit.ts)
- 「检查更新…」与「设置 → 关于」共用软件更新状态。Windows 和 AppImage 下载完新版后提供「更新并重启」，AppImage 保留原有文件路径。Debian 安装包下载完成后提供「打开下载位置」，用户用系统包管理器安装，再重新打开 Pilot。侧栏的更新入口可返回安装包提示。[软件更新界面](../src/renderer/src/components/ai/update-panel.tsx)

### 2.4 侧栏

- **顶部操作。** `打开项目` 和 `新聊天` 两个按钮。新聊天默认落在当前项目。
- **项目分组。** 项目行单行显示文件夹名，完整路径放进 `title`，同名项目才在名称后用灰阶补上一级目录。有聊天的项目行是折叠开关，左侧箭头表示展开状态，折叠状态保存在本地；还没有聊天的项目显示文件夹图标，点击直接在该项目开始新聊天。悬停或键盘聚焦时右侧出现「在此项目新建聊天」。草稿没有会话行可高亮，这时用 `bg-sidebar-accent` 标出草稿所在的项目行。悬停或键盘聚焦时也可以打开项目操作菜单。[侧栏实现](../src/renderer/src/views/Sidebar.tsx)
- **项目操作。** 菜单可在文件管理器中打开目录，也可将项目移出「最近项目」。有聊天的项目在移除后归入「其他项目」，原会话、草稿和项目目录仍可访问。再次打开项目会把它加入最近项目。移除后焦点到原项目在新分组的行，项目行消失时回到「打开项目」。操作失败时在项目行下方显示原因和重试入口。[项目操作实现](../src/renderer/src/views/sidebar/ProjectRow.tsx)
- **会话行。** 单行标题，左侧 12px 状态位（圆点 8px），始终占位以保证标题对齐；右侧相对时间，悬停或键盘聚焦时时间换成置顶和归档按钮，完整时间在 `title` 里。项目内的会话行整体缩进一级。当前会话用 `bg-sidebar-accent` 底色表示，不加粗、不加 ✓。未读会话的标题用 `font-medium`。
- **状态位。** 每行只显示优先级最高的一种，定义见[状态模型](#3-状态模型)。失败使用红色实心点，并提供本地化的状态名称。主进程按会话保存运行结果，后台失败时更新对应行，重启后恢复。新一轮运行期间显示实时状态，随后按新结果更新失败标记。[会话行实现](../src/renderer/src/views/sidebar/SessionRow.tsx)
- **排序。** 组内置顶在前，其余按最近活动时间。项目按最近活动时间。
- **宽度与收起。** 重启后恢复用户拖拽调整的宽度，以及主动设置的展开或收起状态。打开审查面板后空间不足时临时收起，关闭面板或空间恢复后回到用户设定的状态。[侧栏偏好](../src/renderer/src/lib/preferences.ts)

### 2.5 主列顶栏

单行，从左到右：[顶栏实现](../src/renderer/src/components/ai/chat-header.tsx)

1. 会话标题，点击打开重命名对话框，超长截断。首条消息发送前，显示纯文字「新会话」。
2. 项目名芯片，点击打开项目切换菜单：最近项目上下两行显示名称和路径，当前项目右侧打 ✓，末项是 `选择其他文件夹…`。未关联项目时显示橙色的 `选择项目`，`title` 提示当前使用的默认工作目录。已保存且未关联的会话在这里补关联；已关联的会话选另一个项目会在那个项目里开始新聊天。
3. Git 分支，灰阶小字，无 Git 时不显示，主列窄于 32rem 时隐藏。
4. 右侧 `审查` 开关在有工作目录或已保存会话时显示，打开时用 `secondary` 底色表示。开关显示变更文件数和最近一次验证的状态，再次打开时回到本会话上次使用的页签。
5. `⋯` 更多菜单收纳指令来源、重命名、会话指令、导出 Markdown 和归档。导出通过系统保存对话框选择 `.md` 文件，包含会话消息、引用及工具命令和结果。

顶栏右侧只有 `审查` 和 `⋯` 两个控件，新增的会话级动作一律进 `⋯` 菜单。从菜单打开的对话框关闭后，焦点回到 `⋯` 按钮。

### 2.6 首页（空会话）

空会话是用户每天的入口，标题下方直接是输入框，输入框下方按是否有项目分两种：[首页入口实现](../src/renderer/src/components/ai/home-start.tsx)

- **未发送的草稿。** 输入内容、选择项目、模型、权限和计划模式都随草稿保存。应用重启时恢复最近编辑的草稿，重新打开项目时恢复该项目最近编辑的草稿。首条消息被接受后，侧栏才出现会话。
- **已有项目。** 当前项目和分支由主列顶栏的项目芯片显示和切换，首页不重复。输入框下方给 3 个起步任务：`梳理项目结构`、`运行测试并修复`、`审查未提交的改动`。点击后把对应的完整提示填入草稿并聚焦输入框，不直接发送，用户可以改写或用 `Ctrl+Z` 撤回。
- **没有项目。** 输入框下方先是一行橙色的 `未选择项目` 和灰阶说明（任务会在哪个默认工作目录运行），右侧是首要动作 `打开项目…`。其下列出最近 5 个项目，每项两行显示名称和路径，点击后在该项目里开始新聊天。输入框仍可用。
- **没有可用模型。** 标题下方出现配置卡，首要动作换成 `配置模型`，`打开项目…` 降为描边按钮，其余入口保留。同一屏只有一个 `primary` 按钮。

### 2.7 对话流

- **用户消息。** 右对齐气泡，悬停或聚焦时显示下方的复制、编辑并重发、从此处分叉。复制使用可见文案。从此处分叉会将聊天复制到所选消息为止。编辑并重发在新聊天保留所选消息之前的上下文，把原文、图片、文件和技能引用填入输入框供用户修改后发送。[消息操作](../src/renderer/src/components/ai/message-actions.tsx)
- **消息图片。** 在文字气泡上方显示可点击的缩略图和文件名。重开会话可查看大图，按 `Esc` 关闭后回到缩略图。全文搜索可匹配附件名，Markdown 导出记录附件名。[图片预览](../src/renderer/src/components/ai/image-attachments.tsx)
- **助手回合。** 不带头像，与内容列左缘对齐。依次是活动轨迹、正文、文件变更卡。回合给出回答后，活动轨迹整体折成一行摘要「已处理 2 分 13 秒 · 12 步」。有失败步骤时在后面用红色补「2 步失败」，点击可展开。耗时从本次运行开始处理该回合算到完成最终回复，包含中间的工具步骤和审批等待。重试或续跑从本次处理开始计时。缺少计时记录的旧回合只显示步数。没有回答的回合保持展开。回合下方提供复制回复和重试。重试在新聊天中用原始提问重新发起请求。回复之后还有消息时可选择「回到此处」。[回合实现](../src/renderer/src/components/ai/assistant-reply.tsx)
- **回到此处。** 确认对话框显示将移除的消息数和要撤销的文件差异。Git 工作区使用任务检查点，普通文件夹使用内置文件工具的快照。缺少可确认的快照或文件、暂存内容、HEAD 有冲突时，显示原因和重新预览入口。确认后先撤销文件改动，再移除所选回复之后的消息。取消时焦点回到触发按钮，成功后焦点落到输入框。[回退对话框](../src/renderer/src/components/ai/message-rewind-dialog.tsx)
- **工具步骤。** 运行中显示当前步骤，命令的输出跟着展开。成功后折成一行，输出默认折叠，用时一秒以上的步骤在行尾标出耗时。失败时展开并显示错误。命令成功和失败使用相同的输出上限，超长时保留开头和结尾并显示省略的字符数。超时结果显示已运行时长。用户手动开合过的步骤以用户的选择为准。[工具轨迹](../src/renderer/src/components/ai/tool-trace.tsx)
- **审批结果。** 展开该工具步骤可查看本次允许、拒绝、会话授权或已保存授权。后两种同时显示授权范围。决定随会话保存，重开聊天后可回看。工具执行状态继续由实际结果表示。[工具轨迹](../src/renderer/src/components/ai/tool-trace.tsx)
- **计划。** 运行期间固定在输入坞上方，显示当前步骤和进度。回合结束后，最终计划留在该回合的轨迹里：全部完成时收起，还有未完成的步骤时展开。[计划实现](../src/renderer/src/components/ai/plan-card.tsx)
- **上下文压缩。** 对话流在压缩发生处插入灰阶的「已压缩上下文」，默认收起，可用键盘展开摘要和工具输出缩短提示。原始消息和工具输出仍可在对应步骤查看，重开会话后可回看压缩标记。[压缩标记](../src/renderer/src/components/ai/compaction-marker.tsx)
- **技能读取。** 按需读取技能正文或附带文件时，在原有工具轨迹显示「读取技能」及结果。运行技能脚本沿用命令工具和输入坞审批。[技能读取工具](../src/main/agent-host/tools/read-skill.ts)
- **模型错误卡。** 放在输入框上方，用红色图标和标题说明原因，原始错误可通过「错误详情」展开。选择「重试」后从原任务的消息和工具结果继续，焦点回到输入框。凭据、额度或模型不支持此请求时，提供「打开模型设置」。超出上下文上限时提供「压缩并重试」，压缩完成后接着原任务运行。[模型错误卡](../src/renderer/src/components/ai/model-feedback.tsx)
- **中断卡。** 说明中断发生的位置，提供 `继续任务`。
- **会话内查找。** `Ctrl+F` 在对话流上方打开查找栏，显示命中序号和匹配片段。`Enter` 和 `Shift+Enter` 循环跳到下一处和上一处，滚动到命中位置并展开相关轨迹或步骤。可见的匹配文字会突出显示。`Esc` 关闭查找栏并恢复原来的焦点。[查找栏](../src/renderer/src/components/ai/chat-find-bar.tsx)
- **回到最新。** 用户上翻阅读时停止自动吸底，右下角出现回到最新的按钮。轮次刻度轨钉在内容列左侧留白内，留白不足时整体隐藏。

### 2.8 输入坞

从上到下最多三层，全部与内容列对齐：

1. **计划条。** 仅运行期间出现，单行，可展开全部步骤。
2. **排队条。** 有插话排队时出现，显示条数，可清空。
3. **输入框、审批卡或计划审阅卡。** 等待审批或确认计划时用对应的卡片替换输入框，处理后恢复草稿和焦点。

输入框底部工具行，左侧是 `+` 附件、权限模式、上下文用量，右侧是模型与强度、发送或停止。[输入框实现](../src/renderer/src/components/ai/composer.tsx)

- **计划模式。** 在输入框的 `/` 菜单选择「计划模式」，或输入 `/plan` 后按回车。输入框上方显示计划模式状态，再选一次可以退出。会话权限继续显示在底部工具行。规划回合只开放读取、搜索和计划工具，模型可以先在对话中澄清需求，再提交 Markdown 计划。[输入框实现](../src/renderer/src/components/ai/composer.tsx)
- **斜杠命令。** 用方向键选择，按 `Enter` 执行。`/compact [保留重点]` 压缩空闲会话的上下文，`/clear` 或 `/new` 在当前项目打开空白聊天并保留原会话，`/diff` 打开审查面板的「变更」。`/init` 在关联项目中填入生成或更新 `AGENTS.md` 的请求，`/review` 在 Git 项目中填入审查未提交改动的请求。两种请求都可在发送前编辑。[动作定义](../src/renderer/src/hooks/use-workbench-commands.ts)
- **提示词模板。** 从 `/prompt-名称` 或命令面板调用。有参数时先打开填写对话框，同名参数只填写一次。确认后将结果填入草稿，按发送后交给 Agent。取消对话框后回到原来的控件。[参数对话框](../src/renderer/src/components/ai/prompt-template-dialog.tsx)
- **计划审阅。** 成稿后在输入坞显示橙色状态、计划正文和确认后使用的权限。正文可用键盘滚动，底部保留「放弃计划」「编辑计划」和主按钮「确认并执行」。编辑计划时焦点进入文本框，保存或按 `Esc` 取消后回到编辑按钮。保存的计划可以在切换会话或重启后继续审阅。执行权限在启用规划时记录，成稿前主动更改会话权限会更新这项记录。确认时校验当前会话、工作目录和计划版本，按卡内显示的权限执行。放弃后结束本次规划。操作失败时在卡内显示原因和下一步。[计划审阅卡](../src/renderer/src/components/ai/plan-review-card.tsx)
- 上下文用量弹层显示当前占用及会话累计的 token 与费用，弹层打开时随最新用量更新。切换会话或重开应用时，从对应转录恢复累计值。模型上限可用时显示容量和占用百分比，达到 80% 时转橙色，发起模型请求前尝试压缩。上限未知时显示已用 token 和累计值。在空闲会话中可用弹层内的「压缩上下文」或 `/compact [保留重点]` 手动压缩。关闭弹层后焦点返回用量按钮。[用量弹层](../src/renderer/src/components/ai/context-usage.tsx)
- 上下文占用以所选模型的生效上下文长度计算。运行期间使用任务启动时的模型能力。模型选择器在模型名下显示图像输入能力，仅在所选模型支持思考时提供思考强度控件。
- **图片与拖放。** 可粘贴图片、将图片拖入输入坞，或从 `+` 的对话框选择图片，支持 PNG、JPEG、WebP 和 GIF。每条消息最多四张，每张最多 5 MB。缩略图位于输入框上方，可预览或逐张移除。图片随草稿恢复，首条消息发送时才创建会话。工作目录中的其他文件或文件夹拖入后生成 `@` 引用，使用工作目录相对路径。[输入框实现](../src/renderer/src/components/ai/composer.tsx)
- **文本模型。** 切换到文本模型时保留图片草稿，并提示换到支持图像的模型或移除图片后再发送。已有图片可在原消息中查看，文本模型继续会话时使用历史文字和图片占位提示。
- `@` 列出已启用的已安装技能和当前项目技能。`/` 也可选中停用的已安装技能供本次任务读取。项目技能在建议项的说明行标出来源。选择后在输入框插入引用芯片。
- 运行中占位文字说明此时发送是插话。

### 2.9 审批卡

- 标题说明待审批的操作，下方显示实际工作目录。文件操作标明目标路径，命令标明执行环境，MCP 调用标明服务和工具名。待审批使用橙色标题和图标。[审批卡实现](../src/renderer/src/components/ai/permission-card.tsx)
- 命令区显示完整命令，MCP 参数按 JSON 缩进展示。文件新建、覆盖和编辑复用逐行差异，标出增删行及预览上限。无法生成差异时显示原因和原参数。带差异预览的写入在执行前核对文件状态，发现文件变化时提示重新核对和审批。[预览组件](../src/renderer/src/components/ai/permission-preview.tsx)
- 内容区可用鼠标或键盘滚动，允许和拒绝按钮留在卡片底部。处理完最后一项后焦点回到输入框。
- 主按钮 `本次允许`，次按钮 `拒绝`。`⋯` 菜单保留「本会话始终允许」和「总是允许」，每项下方显示实际范围。命令规则包括 Shell 和审批时显示的参数序列作为前缀，后续命令可以追加参数。
- 管道、连接命令和 `$(…)` 子命令的每段都需要匹配已有规则。组合命令中的未授权部分、重定向和无法可靠解析的语法需要逐次审批，卡片直接注明。
- 危险规则优先于会话授权、已保存授权和完全访问模式。命中时输入坞显示红色标题、警示图标和具体原因，只能本次允许或拒绝。再次运行时重新询问。
- 同一批工具调用中需要确认的请求按顺序处理，卡片角上显示「1 / 3」。自动放行的工具不计入审批序号。

### 2.11 命令面板

`Ctrl+K` 打开。结果按操作、项目、会话和设置分区显示，可用底部类别筛选。项目结果显示目录名和完整路径，选择后打开项目。设置结果可按分区说明和设置项名称匹配，选择后聚焦目标分区的页头。用方向键选择，按 `Enter` 执行。[命令面板实现](../src/renderer/src/components/ai/command-palette.tsx)

- **操作。** 入口包括新聊天、打开项目、切换权限与模型、打开审查面板各页签、运行项目默认的测试、类型检查或构建、压缩上下文、切换主题和语言。命令面板与输入框的 `/` 菜单共用动作定义，输入框还可选技能。
- **会话。** 项目范围可选全部项目、单个项目或未关联项目。全文匹配消息、文件名和命令，忽略大小写，结果依次显示会话标题、项目和突出匹配文字的片段。选中结果后打开对应会话并定位到命中处。每次最多显示 80 条全文命中，超过时提示缩小范围。

在「个性化 → 提示词模板」添加、编辑和删除个人模板。命令名称用于 `/prompt-名称`，正文用 `{{参数名}}` 标记需要填写的参数。删除前确认模板名称。[模板设置](../src/renderer/src/views/settings/PromptTemplateSettings.tsx)

- **一个分区只管一件事。** 分区内容超过三个分组，或者混入了另一类对象（例如把聊天列表放进存储页），就拆成新分区，不在一页里堆叠。
- **页头。** 分区标题下方有一句灰阶说明，写这一页管什么。文案放在 `SETTINGS_SECTION_DESCRIPTIONS`，同时是导航搜索的匹配来源。新增设置项时把名称补进 `SETTINGS_SECTION_KEYWORDS`，否则搜不到。
- **行平铺，不套卡片。** 设置行直接铺在页面上，只用细线分隔（`.settings-list`），行内文字与分组标题左对齐，控件靠右。行标题 `text-sm font-medium`，说明 `text-xs text-muted-foreground`。`.settings-card`（带边框和底色的圆角容器）只用于需要整体编辑的对象，目前是提供方列表和提供方表单。
- **分组。** 分区由若干分组组成，统一用 `SettingsGroup`（小标题加可选说明）和 `SettingsItem`（左侧标题与说明，右侧控件）。分区标题 20px，分组标题 `text-sm font-semibold`，行标题 `text-sm font-medium`，三级靠字号和字重区分。只有一个分组的分区不再重复写分组标题。[分组组件](../src/renderer/src/views/settings/SettingsGroup.tsx)
- **导入入口就近放。** 技能和 MCP 服务的导入按钮放在各自分区的列表上方，导入结果显示在按钮下方并立即刷新列表。导入、启停和打开目录失败时，在按钮下方就地显示原因（例如所选目录缺少 `SKILL.md`）。「导入」分区保留为跨类型的批量入口和插件管理，不是唯一入口。
- **技能列表。** 平铺行显示名称、说明和本机或项目来源。本机技能可启停，项目的 `.agents/skills` 和 `.claude/skills` 随项目生效。「查看」打开对话框，显示目录及可滚动阅读的 `SKILL.md`。删除前确认将移除的目录，取消后焦点回到删除入口。关闭详情后返回原技能行，删除成功后焦点回到导入按钮。[技能设置](../src/renderer/src/views/settings/SkillSettings.tsx)
- **控件选择。** 两到三个互斥且需要一眼看全的选项用分段按钮，例如主题。每个选项需要解释后果的用上下结构的选项列表，选中项右侧打 ✓，例如默认权限模式。选项较多或文案较长的用下拉。
- **完全访问。** 默认权限模式和输入坞权限菜单都说明危险命令始终需要确认，MCP 服务可单独要求确认。
- **默认权限。** 在确认模式、只读和完全访问中选择全局默认值。会话可在输入坞单独设置工具审批方式。
- **生效方式。** 选择类设置即时生效。需要校验的表单在分组底部显示保存按钮和结果：没有改动时按钮禁用，保存后留在当前分区并显示「已保存」，不跳回对话。
- **模型能力。** 模型列表的每行提供能力设置按钮，打开后可填写上下文长度、输出上限、图像输入和思考支持。留空或选择「自动」采用目录数据和默认值。应用后通过提供方页面保存，关闭对话框后焦点回到该模型的按钮。读取模型列表后可以更新已保存模型的目录数据，逐模型覆盖继续生效。[模型能力表单](../src/renderer/src/views/settings/ModelCapabilitiesDialog.tsx)
- **空状态。** 列表为空时保留分组，用 `ListEmpty` 显示两行：第一行说明现在没有什么，第二行灰阶小字说明怎样让内容出现在这里。不隐藏整组。[空状态组件](../src/renderer/src/components/ai/list-empty.tsx)
- **权限规则。** 平铺列表显示工具、范围和撤销按钮。命令范围包括 Shell 和命令前缀，文件范围显示路径前缀。内置工具显示与审批卡一致的名称，MCP 工具显示原名。旧的无范围命令授权已停用，行内用橙色提示下次运行时重新授权，仍可撤销旧条目。
- **只加有行为的设置。** 设置项必须对应已实现的行为。自动压缩和回合后验证命令的设置随对应功能一起加入。
- **存储位置。** 只在本机界面生效的偏好（主题、语言、发送方式）存渲染层本地，其余走主进程设置。

## 3. 状态模型

同一种状态在所有位置使用同一组颜色、图标和文案。

| 状态 | 颜色 | 侧栏状态位 | 主列与输入坞 | 窗口外 |
| --- | --- | --- | --- | --- |
| 待审批 | 橙 | 橙色实心点 | 审批卡替换输入框 | 系统通知，Windows 任务栏闪烁 |
| 运行中 | emerald | 绿色转圈 | 当前步骤、计划条、停止按钮 | 无 |
| 停止中 | 灰阶 | 灰色转圈 | 停止按钮禁用并显示「正在停止」 | 无 |
| 失败 | 红 | 红色实心点 | 错误卡和下一步动作 | 系统通知，Windows 任务栏闪烁 |
| 已中断 | 灰阶 | 灰色空心点 | 中断卡和继续任务 | 无 |
| 等待确认计划 | 橙 | 橙色实心点 | 计划审阅卡替换输入框 | 系统通知，Windows 任务栏闪烁 |
| 已完成未读 | 强调色 | 强调色实心点 | 无 | 系统通知，Windows 任务栏闪烁 |
| 空闲 | 无 | 无 | 发送按钮 | 无 |

- 状态位的优先级从上到下递减，每行只显示一种。
- 模型自动重试属于运行中。输入坞状态行用运行色显示本次重试序号和等待时间，发起请求后显示「正在重试」。原有「停止」按钮可以立即取消等待或正在重试的请求。
- 压缩上下文也属于运行中。输入坞状态行用运行色显示「正在压缩上下文…」，可用「停止」取消。正在压缩的会话保留输入框与草稿。
- 窗口失焦、最小化或对应会话不可见时，发送待审批、待确认计划、完成和失败的系统通知。进入设置视图或打开盖住对话的侧栏与审查面板时，会话也视为不可见。每次运行的待审批通知只提醒一次。
- 系统通知显示对应会话的标题。点击后唤起窗口并回到该会话，将键盘焦点移到审批卡、计划审阅卡、错误操作或输入区。「常规 → 通知」中的桌面通知默认开启，关闭后同时停用系统通知和任务栏提醒。后台完成仍标为未读，回到会话后清除。[通知实现](../src/main/task-notifications/index.ts)
- 验证命令的状态独立于 Agent 运行，显示在审查开关的状态点和验证页签上。

### 4.1 颜色

| 强调色 | `brand`（`bg-brand`、`text-brand`），焦点环 `ring-ring` 与它同值 |
| 对话中的工作区链接与引用芯片 | `var(--workspace-reference)`，与强调色同值 |
| 次级文字 | `text-muted-foreground` |
| 分隔线 | `border-border`，列内弱分隔用 `border-border/65` |

强调色只用在五处：未读圆点、链接与引用、焦点环、开关的开启态、复选框的选中态。主按钮保持 `primary`，运行和成功保持 emerald，菜单里的选中标记 ✓ 保持文字色。新增用法前先确认它属于这五类，避免界面里出现多个争抢注意力的蓝色块。

语义色分四级：

- **红 `destructive`。** 破坏性动作和真实危险，例如拒绝、删除、错误、危险命令。
- **橙 `text-amber-600 dark:text-amber-400`。** 需要用户留意但不具破坏性，例如完全访问模式、待审批、上下文将满、未选择项目。
   审批标题、权限菜单标题和旧规则的行内提示在亮色用 `text-amber-700`。带橙色底的「完全访问」标记在亮色用 `text-amber-800`，覆盖常态和悬停态的文字对比度。
- **emerald。** 运行中、成功、流式光标。
- **灰阶。** 次级文字和常态。

带语义色的图标，同一行的标题文字跟随同色，说明行保持灰阶。差异的增删行使用绿色和红色背景，同时保留 `+` 和 `-` 符号。

### 4.2 字号与字重

| 层级 | 规格 | 用途 |
| --- | --- | --- |
| 页面标题 | `clamp(1.375rem, 2.5vw, 1.75rem)`，`font-semibold` | 首页标题 |
| 分区标题 | 20px（`text-xl`），`font-semibold` | 设置分区标题 |
| 分组标题 | 14px（`text-sm`），`font-semibold` | 设置分组标题 |
| 正文 | 14px（`text-sm`），行高 24px | 消息正文、输入框、表单、按钮、设置行标题（`font-medium`） |
| 界面文字 | 13px | 顶栏标题、侧栏行、菜单、标题栏 |
| 辅助文字 | 12px（`text-xs`），`text-muted-foreground` | 说明行、时间、路径、角标 |
| 代码 | 等宽，13px | 命令、差异、终端、路径 |

字重只用 `font-normal`、`font-medium` 和 `font-semibold`。`font-semibold` 只给页面、分区和分组标题。`font-medium` 用于行标题、卡片标题和未读会话的标题，不用加粗表示选中。

### 4.3 尺寸与间距

- 间距取 4px 的倍数。行内图标与文字间距 6–8px，列表行内边距 8–12px，分区间距 28px。
- 圆角以 `--radius`（10px）为基准。工作卡片 `rounded-xl`。按钮、单行输入和下拉触发器是胶囊形，多行输入、提示卡和设置卡片同为 `rounded-2xl`，这些都由 `components/ui/` 的组件自带，使用处不再覆盖圆角。列表行、菜单项和侧栏行 `rounded-lg`，芯片 `rounded-sm` 或全圆。
- 固定高度：标题栏 38px，主列顶栏与面板页签栏 40px，侧栏会话行 30–32px，标题栏控件 28px，小按钮 28px，默认按钮 32px。
- 图标使用 lucide，界面内 16px，辅助信息旁 12–14px，描边 1.7 左右。纯图标按钮必须有 `aria-label` 和 `title`。

### 4.4 动效

- 展开、收起和面板滑入 150–200ms，使用缓出曲线。拖动调宽期间关闭宽度过渡。
- 流式输出不加逐字动画。转圈只用于确实在等待的状态。
- 遵循系统的减少动态效果设置。

## 5. 组件规则

### 5.1 选哪种容器

| 场景 | 容器 |
| --- | --- |
| 持续查看、与对话并行的内容 | 审查面板页签 |
| 需要用户确认范围或不可撤销的操作 | 对话框 |
| 少量选项或一次性的设置 | 下拉菜单或弹出层 |
| 阻塞当前任务、必须处理的请求 | 输入坞内的卡片 |
| 操作结果反馈 | 就地显示在触发位置旁。跨区域的结果用可自动消失的提示条 |

归档、恢复聊天、复制聊天全文和移除最近项目的提示条放在当前可见列的顶部。对话中放在会话顶栏下方，设置视图中放在主列顶部。窄窗打开覆盖式侧栏或审查面板时，提示条随可操作的列显示。提示默认 4 秒后消失，支持键盘关闭。失败时显示原因和可执行的下一步。[提示条组件](../src/renderer/src/components/ai/feedback-bar.tsx)

### 5.2 菜单与列表

- 次级信息使用上下结构。主标题一行，说明另起一行，`text-xs text-muted-foreground`。不把说明用「·」挤进标题行。
- 带说明行的条目用 `items-start`，图标 `mt-0.5` 与首行对齐，内容块 `flex-col gap-0.5`。
- 选中项在右侧显示 `CheckIcon`，不用加粗或变色表示。
- 下拉弹层宽度随内容自适应，最小 `min-w-40`，不使用 `w-(--anchor-width)` 锁定锚宽。
- 路径过长时保留末尾，用 `[direction:rtl]` 配合 `<bdi dir="ltr">` 截断前部。
- `DropdownMenuLabel` 放在 `DropdownMenuGroup` 内。自定义触发器用 `render={<button />}`。

### 5.3 按钮

- 每个区域最多一个主按钮。次要动作用 `outline`，行内和工具行动作用 `ghost`，破坏性动作用 `destructive`，并在不可撤销时二次确认。
- 按钮文字是动词短语，例如「本次允许」「运行测试」「提交 3 个文件」。打开对话框或系统选择器的入口以「…」结尾。
- 进行中的按钮禁用并改为进行时文案，例如「保存中…」。

### 5.4 覆盖物

刻度轨、小地图等覆盖物钉在内容列的留白内，用 ResizeObserver 测量主列宽度后定位。留白不足时整体隐藏，不遮挡正文。

### 5.5 空态、加载与错误

- 空态说明这里会出现什么，并给出一个动作。动作按钮已经在列表上方时，空态只写说明，不重复放按钮。
- 加载超过 300ms 才显示转圈或骨架。列表刷新时保留旧内容。
- 错误就地显示，红色文字加 `role="alert"`，内容经 `localizeError` 本地化。
- React 组件异常时，工作卡片内显示出错原因、「重新加载」和「查看日志」，保留可拖动的标题栏和系统窗控。键盘焦点落在「重新加载」。[界面错误边界](../src/renderer/src/components/app-error-boundary.tsx)
- 渲染进程退出或失去响应时，主进程用原生对话框提示重新加载。同一窗口加载后恢复当前会话、草稿、任务进度和待审批请求。如果界面自行恢复响应，无响应提示会关闭。[窗口恢复](../src/main/window-recovery.ts)

## 7. 文案与多语言

- 界面文案用 `t("中文原文", locale)`，中文原文即翻译键。新增文案同时补英文词条。
- 用完整的短句，直接说明对象和结果。不使用感叹号，不用「请稍候」之类不含信息的提示。
- 中文与英文、数字之间留一个空格。省略号用「…」。
- 布局按英文长度验收，按钮和页签在英文下不换行、不截断关键词。
- 时间用相对时间，悬停显示完整时间。耗时写成「2 分 13 秒」或 `2m 13s`。

## 8. 可访问性

- 文字与背景的对比度不低于 4.5:1，辅助文字和图标不低于 3:1，亮色与暗色都要检查。
- 状态不只靠颜色表达，同时使用图标形状或文字。
- 流式内容区域使用礼貌播报，审批和错误使用 `role="alert"`。
- 界面缩放到 150% 时主流程可用。
